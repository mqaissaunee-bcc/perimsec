    01

    What this lab is for

    A Security rule decides whether a session is allowed. A Security Profile decides what happens to the content inside an allowed session. An allow rule with no profiles is an open door with no one watching it, which is exactly the state the firewall is in at the start of this lab.

    The before-and-after design is the point. You'll see attacks, a forbidden file type, a file full of Social Security numbers, and a lookup for a banned domain all pass. Then the same tests produce block pages, a sinkholed DNS answer, and a full Threat log.

    • You'll leave with: Corp-AV, Corp-Vuln, Corp-FileBlock, Corp-DataFilter, and Corp-AS (with an EDL sinkhole), grouped in Corp-Profiles-Group on all six allow rules.
    • Builds on: Module 10. Simulation 10.1 (which profile catches it?) and 10.2 (follow a sinkholed lookup) are the best preparation.
    • Sets up: Labs 9 and 10 add URL Filtering and WildFire profiles to this same group; the capstone rebuilds it from scratch.

    Walkthrough of the detailed steps

    2.1Load the lab configuration

    Every lab starts from a known baseline, so your firewall matches the guide no matter what you did last time.

    1. On the client desktop, log in as lab-user, open Firefox, and browse to https://192.168.1.254. Log in as admin with the password from Lab Settings. If the login page does not appear, wait 1 to 3 minutes for the firewall to finish booting and refresh.
    2. Go to and click Load named configuration snapshot. Choose edu-210-11.0a-08.xml and click OK, then Close.
    3. Open Tasks (lower right) and confirm the Load task shows completed.
    4. Click Commit (upper right), then Commit in the dialog, and wait for it to finish.

    Loading is not committing

    A loaded snapshot replaces only the candidate configuration. Until you commit, the firewall is still running whatever was there before, and nothing in the lab will match the guide.

    2.2Generate traffic without Security Profiles

    1. Open Remmina, double-click Server-Extranet, and start the attack script. Let it run uninterrupted (about 6 minutes) and minimize the window.

    1. In a new Firefox window, open http://192.168.50.80/badtarfile.tar and Save it. The download succeeds.
    2. In a new tab, open http://192.168.50.80/companyssns.txt. The file displays. Close Firefox.
    3. In the client terminal, look up a domain you'll later sinkhole. You get a normal public address.

    2.3Create an antivirus profile

    1. Go to , check default, and click Clone, then OK.
    2. Open default-1, rename it Corp-AV, description Standard antivirus profile for all security policy rules. Click OK.

    Why clone?

    Predefined profiles can't be edited. Cloning gives you a copy you can tune later without starting from scratch.

    2.4Create a vulnerability protection profile

    1. Go to , check strict, Clone, OK.
    2. Open strict-1, rename it Corp-Vuln, description Standard vulnerability profile for all security policy rules.

    2.5Create a file blocking profile

    1. Go to , check strict file blocking, Clone, OK.
    2. Open strict file blocking-1, rename it Corp-FileBlock, description Standard file blocking profile for all security policy rules.

    2.6Create a data filtering profile

    1. Go to and click Add. Name US-SSNs, description US Social Security Numbers, Pattern Type Predefined Pattern. Add Social Security Numbers and Social Security Numbers (without dash separator). Click OK.
    2. Go to and click Add. Name Corp-DataFilter, description Standard data filtering profile for all security rules.
    3. Add the US-SSNs pattern. Set Alert Threshold to 1, Block Threshold to 3, and Log Severity to critical. Click OK.

    "More than three" means three or more

    The guide says the profile blocks files with more than three SSNs, but a block threshold of 3 blocks at three matches. One or two matches only alert.

    2.7Create an anti-spyware profile

    1. Go to , check strict, Clone, OK.
    2. Open strict-1, rename it Corp-AS, description Standard anti-spyware profile for all security policy rules.

    2.8Create an external dynamic list of malicious domains

    1. Go to and click Add. Read the notice about domain tokens and click Cancel.
    2. Name malicious-domains-edl, Type Domain List, description Custom list of bad domains maintained on Extranet server, Source http://192.168.50.80/malicious-domains.txt. Check Automatically expand to include subdomains. Check for updates Every Five Minutes. Click OK.
    3. Open the list again, cancel the notice, and click Test Source URL. It should report the URL is accessible.

    What's on the list

    quora.com and producthunt.com, chosen for the lab. They aren't actually malicious.

    2.9Sinkhole the EDL in the anti-spyware profile

    1. Open Corp-AS and select the DNS Policies tab.
    2. Under External Dynamic Lists, set the Policy Action for malicious-domains-edl to sinkhole. Click OK.

    Name drift

    The guide calls the profile "Corporate-AS" once. It's the Corp-AS you just created.

    2.10Create a Security Profile Group

    1. Go to and click Add. Name it Corp-Profiles-Group.
    2. Choose Corp-AV, Corp-AS, Corp-Vuln, Corp-FileBlock, and Corp-DataFilter in their drop-downs. Leave URL Filtering and WildFire Analysis at None. Click OK.

    Screenshot 3 The Corp-Profiles-Group window with all five Corp- profiles selected.

    2.11Apply the group to every allow rule

    1. In , open each allow rule in turn. On Actions, set Profile Type to Group and choose Corp-Profiles-Group. Click OK.
    2. Do all six: Allow-PANW-Apps, Users_to_Extranet, Users_to_Internet, Extranet_to_Internet, Extranet_to_User_Net, and the Acquisition allow rule.
    3. Hover over each rule's profile icon to confirm, then commit.

    The Acquisition rule's name

    The guide lists Acquisition-Allow-All. If your baseline carries Lab 11's rename, it's Allow-Corp-Apps (and Allow-Mktg-Apps also allows traffic). Apply the group to every rule whose action is Allow, whatever it's called.

    A skipped rule is uninspected traffic

    Profiles only act on traffic matched by a rule that carries them. Block and deny rules don't need them.

    2.12Test again with Security Profiles

    1. In the Server-Extranet window, run ./malwareattacks.sh again (same folder) and let it finish.
    2. Open a private Firefox window (right-click Firefox in the taskbar) and request http://192.168.50.80/badtarfile.tar. You get File Transfer Blocked.
    3. In a new tab, request http://192.168.50.80/companyssns.txt. You get Data Transfer Blocked. Close Firefox.
    4. In the terminal, run the dig again. It now returns sinkhole.paloaltonetworks.com.
    Commandlab-user@client-a:~/Desktop/Lab-Files$ dig @8.8.8.8 www.quora.com
    1. Go to , clear filters, and page through entries for spyware, vulnerabilities, file blocking, data filtering, and the DNS sinkhole.

    Why a private window

    It avoids Firefox's cache, which could serve the earlier, unblocked copies of the files.

    The sinkhole answer is success

    It means the firewall intercepted the lookup and replaced the answer. A real infected host would then try to connect to the sinkhole address, and that attempt identifies it in the Traffic log.

    The high-level steps stop early

    Task 1 ends at the tar file. Do the SSN file, the dig, and the Threat log review whichever version you follow; they prove the data filtering and sinkhole work.

    06

    How this looks on a real firewall

    • Profiles on every allow rule. Best practice is a profile group on every allow rule. Many teams name their group default so new rules get it automatically.
    • Start strict, tune exceptions. Use strict or best-practice profiles and handle false positives with specific exceptions, not by weakening the whole profile.
    • Sinkhole with internal DNS in mind. With an internal resolver, the Threat log shows the resolver as the source; you find the infected host by who connects to the sinkhole address afterward.
    • Data filtering is not full DLP. It's a useful backstop; dedicated DLP (Module 16) handles sensitive data more completely.
    • Other vendors: Fortinet security profiles, Cisco Snort IPS and malware policies, and Check Point Threat Prevention play the same roles.
    07

    Check yourself

    An allow rule has no profiles. What does the firewall do with malware inside that session?

    Nothing. Profiles are what inspect allowed traffic.

    Which profile blocked badtarfile.tar, and does it look at what's inside the file?

    File Blocking. It acts on file type, not content.

    With alert threshold 1 and block threshold 3, what happens to a file with two SSNs?

    It's allowed with an alert logged. Three or more are blocked.

    Why is dig returning sinkhole.paloaltonetworks.com a success?

    The anti-spyware profile intercepted a lookup for a listed domain and replaced the answer.

    Why clone the predefined profiles instead of editing them?

    Predefined profiles are read-only.
