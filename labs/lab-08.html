Lab 8: Blocking Known Threats Using Security Profiles

Allowed traffic still needs inspecting. You run attacks and risky downloads through the firewall unprotected, then build antivirus, vulnerability, file blocking, data filtering, and anti-spyware profiles, add a DNS sinkhole fed by an external dynamic list, bundle them in a profile group, attach it to every allow rule, and run the same tests again.

    01

    What this lab is for

    A Security rule decides whether a session is allowed. A Security Profile decides what happens to the content inside an allowed session. An allow rule with no profiles is an open door with no one watching it, which is exactly the state the firewall is in at the start of this lab.

    The before-and-after design is the point. You'll see attacks, a forbidden file type, a file full of Social Security numbers, and a lookup for a banned domain all pass. Then the same tests produce block pages, a sinkholed DNS answer, and a full Threat log.

    • You'll leave with: Corp-AV, Corp-Vuln, Corp-FileBlock, Corp-DataFilter, and Corp-AS (with an EDL sinkhole), grouped in Corp-Profiles-Group on all six allow rules.
    • Builds on: Module 10. Simulation 10.1 (which profile catches it?) and 10.2 (follow a sinkholed lookup) are the best preparation.
    • Sets up: Labs 9 and 10 add URL Filtering and WildFire profiles to this same group; the capstone rebuilds it from scratch.

    06

    How this looks on a real firewall

    • Profiles on every allow rule. Best practice is a profile group on every allow rule. Many teams name their group default so new rules get it automatically.
    • Start strict, tune exceptions. Use strict or best-practice profiles and handle false positives with specific exceptions, not by weakening the whole profile.
    • Sinkhole with internal DNS in mind. With an internal resolver, the Threat log shows the resolver as the source; you find the infected host by who connects to the sinkhole address afterward.
    • Data filtering is not full DLP. It's a useful backstop; dedicated DLP (Module 16) handles sensitive data more completely.
    • Other vendors: Fortinet security profiles, Cisco Snort IPS and malware policies, and Check Point Threat Prevention play the same roles.
    07

    Check yourself

    An allow rule has no profiles. What does the firewall do with malware inside that session?

    Nothing. Profiles are what inspect allowed traffic.

    Which profile blocked badtarfile.tar, and does it look at what's inside the file?

    File Blocking. It acts on file type, not content.

    With alert threshold 1 and block threshold 3, what happens to a file with two SSNs?

    It's allowed with an alert logged. Three or more are blocked.

    Why is dig returning sinkhole.paloaltonetworks.com a success?

    The anti-spyware profile intercepted a lookup for a listed domain and replaced the answer.

    Why clone the predefined profiles instead of editing them?

    Predefined profiles are read-only.
