    01

    What this lab is for

    A firewall that blocks threats but can't tell you what happened is only half useful. Analysts, auditors, and managers all ask questions: what's attacking us, who's using that application, did the block actually work? This lab tours every place PAN-OS keeps answers and practices the habit that makes them useful: start broad, then filter.

    The tools go from summary to detail. The Dashboard shows the last hour at a glance. The ACC lets you pivot on any value with global filters. Logs show every event. App Scope shows trends. Reports package it for other people.

    • You'll leave with: practice with each tool, all predefined reports enabled, and a custom report named Apps Used by Internal Zones.
    • Builds on: Module 14. Simulation 14.1 (where would you look?) and 14.2 (log filter builder) are direct rehearsals.
    • Sets up: the troubleshooting you'll do in the capstone, and any job that involves a SIEM.

    03

    Walkthrough of the detailed steps

    2.1Load the lab configuration

    Every lab starts from a known baseline, so your firewall matches the guide no matter what you did last time.

    1. On the client desktop, log in as lab-user, open Firefox, and browse to https://192.168.1.254. Log in as admin with the password from Lab Settings. If the login page does not appear, wait 1 to 3 minutes for the firewall to finish booting and refresh.
    2. Go to and click Load named configuration snapshot. Choose edu-210-11.0a-13.xml and click OK, then Close.
    3. Open Tasks (lower right) and confirm the Load task shows completed.
    4. Click Commit (upper right), then Commit in the dialog, and wait for it to finish.

    Loading is not committing

    A loaded snapshot replaces only the candidate configuration. Until you commit, the firewall is still running whatever was there before, and nothing in the lab will match the guide.

    2.2Generate traffic

    1. Open Remmina and double-click Server-Extranet.
    2. Run the script and press Enter to start it. Let it run 5 to 7 minutes, uninterrupted.
    Commandpaloalto42@extranet1:~$ ./UsingLogs-V1.sh
    1. When it finishes, close the session and Remmina.

    Don't start early

    Widgets, the ACC, and App Scope summarize what's in the logs. Before the script finishes, they're thin or empty.

    2.3Recent threats on the Dashboard

    1. On the Dashboard, click Widgets > Logs > Threat Logs. (Greyed out means it's already shown.)
    2. Add Widgets > Logs > URL Filtering Logs and Logs > Data Filtering Logs.

    Q1: Any threats in the Threat Logs widget?

    a. Yes, once the script has run. It shows the 10 most recent threats from the last hour.

    Q2: Any URLs in the URL Filtering Logs widget?

    a. Yes. The script's browsing generates URL entries.

    Q3: Any files in the Data Filtering Logs widget?

    It may be b. No. The guide says so too: the widget only shows the last hour, and the script may not produce data filtering events in that window.

    Screenshot 1 The Dashboard showing the Threat Logs and URL Filtering Logs widgets with entries.

    2.4Recent applications on the Dashboard

    1. Add Widgets > Application > Top Applications, then Application > Top High Risk Applications.
    2. Risk 4 applications show in orange, risk 5 in red. Allow 3 to 5 minutes if they're empty.

    2.5Threats in the ACC

    1. Click the ACC tab. Under Global Filters, click Clear all if anything's there. Set Time to Last Hour and choose the Threat Activity tab.
    2. In the Threat Activity table, hover over a high severity item and click the small arrow to promote it to a global filter.
    3. Find it under Global Filters, note how every widget changes, then click Clear all.

    Q4: Do you see threats in the Threat Activity widget?

    b. Yes, multiple threats are listed: some mix of flood, scan, spyware, packet, vulnerability, and virus.

    Q5: Did the table change to show only high severity?

    a. Yes. Promoting a value makes it a global filter for every widget.

    Q6: Is high severity listed in the Global Filters box?

    b. Yes, the high severity is listed.

    Q7: Which widgets show hosts that visited or resolved malicious domains?

    a and d: Hosts Visiting Malicious URLs and Hosts Resolving Malicious Domains.

    "Last seven days" versus Last Hour

    The guide's notes mention counts "in the last seven days," but step 1 sets the time to Last Hour. Whatever range you pick is the range the widgets show.

    Screenshot 2 The ACC with high severity applied as a global filter.

    2.6Applications in the ACC

    1. In the ACC, open Network Activity. Collapse the sidebar with its small arrow for more room.
    2. In Application Usage, choose the sessions radio button and hover over web-browsing in the chart.
    3. In the table below, hover over web-browsing and click the left arrow to make it a global filter. Reopen the sidebar to see it.
    4. Scroll to Rule Usage, choose bytes, and set the time to Last Hour.
    5. Click Jump to Logs in that widget and choose the Traffic log.
    6. Clear the log filter, return to the ACC, and click Clear all under Global Filters.

    Q8: Which rules allowed web-browsing?

    Read the Rule Usage widget. In this baseline, expect Users_to_Internet and Users_to_Extranet (b and d). Allow-Corp-Apps also appears if web-browsing is one of Acquisition's approved apps.

    Q9: Which log opens?

    a. Traffic.

    Q10: Which filters were applied automatically?

    a and b: a time range filter and the application filter you promoted. Check the filter text in the log to confirm.

    Screenshot 3 The Traffic log opened from Jump to Logs, showing the filter it applied.

    2.7Threats in the Threat log

    1. Go to and clear any filter.
    2. Click + (Add Log Filter): and, Severity, greater than or equal, high. Add, Apply, then click the arrow to run it.
    Log filter( severity geq high )
    1. Clear it, then build: and, Source User, equal, chicago\escrooge. Add, Apply, run it.
    Log filter( user.src eq 'chicago\escrooge' )
    1. Clear the filter.

    Q11: Is the log showing only high severity or greater?

    a. True.

    Typing the user filter yourself

    The Filter Builder adds the quotes for you. If you type it, the backslash means you need straight single quotes, as above.

    Screenshot 4 The Threat log filtered to severity high or greater.

    2.8Applications in the Traffic log

    1. Go to and clear any filter.
    2. Add a filter: and, Source Zone, equal, Acquisition. Apply and run it.
    Log filter( zone.src eq Acquisition )
    1. Open Add Log Filter again. Edit the existing clause to Users_Net, then add and, Application, equal, web-browsing. Apply and run.
    Log filter( zone.src eq Users_Net ) and ( app eq web-browsing )

    Q12: Is the log showing only Acquisition traffic?

    a. True.

    Q13: Is it showing only web-browsing from Users_Net?

    a. True.

    The guide says "Threat log" here

    Steps 5 and 11 say to apply the filter to the Threat log, and step 6 says it shows "threats." You're in the Traffic log, filtering sessions. One note also mentions a "dmz zone"; it means Acquisition.

    Screenshot 5 The Traffic log filtered to web-browsing from Users_Net.

    2.9App Scope Threat Monitor

    1. Go to .
    2. Click Last 7 days, then change Top 10 to Top 25.
    3. Change Threat to Source User, choose Show all threat types, and hover over a bar to see the user and count.

    Screenshot 6 The Threat Monitor showing the top 25 by source user over the last 7 days.

    2.10Enable predefined reports

    1. Go to and click the gear on Logging and Reporting Settings.
    2. On the Pre-Defined Reports tab, click Select All and click OK. Commit.

    2.11Read predefined reports

    1. Go to .
    2. In the report list on the right, expand Application Reports and click top-applications. It shows the previous day's top applications.
    3. Open Traffic Reports > top-sources as well.

    Predefined, not Custom

    The guide says to expand Custom Reports to find top-applications. top-applications and top-sources are predefined reports, listed by category in the right-hand panel.

    Grey dates

    Reports are generated daily, so a lab environment may only have data for some days. Click through the calendar dates until one shows data.

    Screenshot 7 The top-applications predefined report with data.

    2.12Build a custom report

    1. Go to and click Add.
    2. Name Apps Used by Internal Zones, Database Summary Databases > Traffic, Scheduled checked, Time Frame Last 7 Days, Sort By Sessions and Top 100, Group By Source Zone and 5 Groups. Selected Columns: Source Zone, Action, Application, Bytes.
    3. Click Filter Builder: and, Source Zone, not equal, Internet. Add, Apply, OK.
    4. Open the report and click Run Now. Read the results by zone.
    Log filter( zone.src neq Internet )

    Ask why each zone appears

    The filter excludes traffic from the internet, which leaves the internal zones. Notice which ones show up (the guide mentions Extranet and Acquisition) and think about why Users_Net might be small or missing in this data.

    Screenshot 8 The Apps Used by Internal Zones report results grouped by source zone.

    Filters from this lab

    PurposeFilter
    High or worse( severity geq high )
    One user( user.src eq 'chicago\escrooge' )
    One zone( zone.src eq Acquisition )
    Zone and app( zone.src eq Users_Net ) and ( app eq web-browsing )
    Exclude internet( zone.src neq Internet )

    The CLI view of the same logs

    direction equal backward lists the newest entries first. The web interface is far easier for filtering; the CLI matters when you only have SSH.

    Commandadmin@firewall-a> show log threat direction equal backward
admin@firewall-a> show log traffic direction equal backward

    06

    How this looks on a real firewall

    • Forward logs off the firewall. Firewalls keep limited history. Production deployments forward logs to Panorama, Strata Logging Service, or a SIEM through log forwarding profiles (Module 14).
    • Schedule the reports people need. Weekly top threats and high-risk applications, emailed as a PDF summary, is a common deliverable for managers and auditors.
    • Build saved filters. Analysts keep a library of filters for recurring questions: a user, a server, denied traffic to a sensitive zone.
    • Correlate. Single events rarely tell the story. Correlation objects and SIEM rules connect a spyware hit, a sinkholed lookup, and odd traffic from the same host.
    • Other vendors: FortiView and FortiAnalyzer, Cisco FMC dashboards, and Check Point SmartView play the ACC and reporting roles.
    07

    Check yourself

    You want every widget in the ACC to show only one source user. What do you do?

    Promote that user to a global filter.

    The ACC shows a spike in a threat. Where do you go for the individual events?

    The Threat log, using Jump to Logs or a filter on that threat.

    Write a Threat log filter for critical threats from the Acquisition zone.

    ( severity eq critical ) and ( zone.src eq Acquisition )

    Why might a predefined report show no data for today?

    Predefined reports are generated daily from the previous day's data.

    What does the custom report's filter ( zone.src neq Internet ) leave out, and why?

    Traffic that starts on the internet, so the report focuses on what internal zones are using.
