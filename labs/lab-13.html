    01

    What this lab is for

    A firewall that blocks threats but can't tell you what happened is only half useful. Analysts, auditors, and managers all ask questions: what's attacking us, who's using that application, did the block actually work? This lab tours every place PAN-OS keeps answers and practices the habit that makes them useful: start broad, then filter.

    The tools go from summary to detail. The Dashboard shows the last hour at a glance. The ACC lets you pivot on any value with global filters. Logs show every event. App Scope shows trends. Reports package it for other people.

    • You'll leave with: practice with each tool, all predefined reports enabled, and a custom report named Apps Used by Internal Zones.
    • Builds on: Module 14. Simulation 14.1 (where would you look?) and 14.2 (log filter builder) are direct rehearsals.
    • Sets up: the troubleshooting you'll do in the capstone, and any job that involves a SIEM.

    2.7View threat information in the Threat log

    You check whether high and critical threats are blocked, then look at threats from a single user.

    🧱On Firewall web interfacefirewall-a at https://192.168.1.254, in Firefox on the Client

    1. Select . At the upper right, click the X in the filter area to remove any filter.
    1. Click the + icon in the filter area to open the Add Log Filter window.
    2. Select Connector and, Attribute Severity, Operator greater than or equal, Value high. Click Add.
    3. In the Add Log Filter window, click Apply. (Once you know the syntax, you can type filters straight into the field.)
    4. With the filter string in the filter box, click the right-arrow (Apply Filter) icon to apply it.
    Log filter( severity geq high )

    Guide question Q11

    Is the Threat log filtered to display only threats of high severity or greater?

    Answer: a. True.

    Screenshot 4 The Threat log filtered to severity high or greater.

    1. The Threat log shows only threats of high severity or greater.
    2. Click the X in the filter area to remove the filter.
    1. Click the + icon in the filter area to open the Add Log Filter window.
    2. Select Connector and, Attribute Source User, Operator equal, Value chicago\escrooge. Click Add.
    3. In the Add Log Filter window, click Apply. (Once you know the syntax, you can type filters straight into the field.)
    4. With the filter string in the filter box, click the right-arrow (Apply Filter) icon to apply it.
    Log filter( user.src eq 'chicago\escrooge' )

    Typing the user filter yourself

    The Filter Builder adds the quotes for you. If you type it, the backslash means you need straight single quotes, as above.

    1. The Threat log shows only threats from Source User chicago\escrooge.
    2. Click the X to clear the filter. (URL Filtering, WildFire Submissions, and Data Filtering logs take the same kind of filters.)
    3. Leave the firewall open and continue to the next task.

    How this looks on a real firewall

    • Forward logs off the firewall. Firewalls keep limited history. Production deployments forward logs to Panorama, Strata Logging Service, or a SIEM through log forwarding profiles (Module 14).
    • Schedule the reports people need. Weekly top threats and high-risk applications, emailed as a PDF summary, is a common deliverable for managers and auditors.
    • Build saved filters. Analysts keep a library of filters for recurring questions: a user, a server, denied traffic to a sensitive zone.
    • Correlate. Single events rarely tell the story. Correlation objects and SIEM rules connect a spyware hit, a sinkholed lookup, and odd traffic from the same host.
    • Other vendors: FortiView and FortiAnalyzer, Cisco FMC dashboards, and Check Point SmartView play the ACC and reporting roles.

    Check yourself

    You want every widget in the ACC to show only one source user. What do you do?

    Promote that user to a global filter.

    The ACC shows a spike in a threat. Where do you go for the individual events?

    The Threat log, using Jump to Logs or a filter on that threat.

    Write a Threat log filter for critical threats from the Acquisition zone.

    ( severity eq critical ) and ( zone.src eq Acquisition )

    Why might a predefined report show no data for today?

    Predefined reports are generated daily from the previous day's data.

    What does the custom report's filter ( zone.src neq Internet ) leave out, and why?

    Traffic that starts on the internet, so the report focuses on what internal zones are using.
