Lab 10: Blocking Unknown Threats with WildFire

    01

    What this lab is for

    Lab 8's profiles match known threats. A brand-new piece of malware has no signature yet, so it walks past them. WildFire closes that gap: the firewall forwards unknown files to a cloud sandbox, which runs them, watches what they do, and returns a verdict (benign, grayware, phishing, or malicious). A malicious verdict produces a signature that protects every subscribing firewall.

    This lab is mostly about watching that flow happen and reading what WildFire tells you, which makes it shorter than most. The wait for a verdict is real; plan for it.

    • You'll leave with: a Corp-WF profile in Corp-Profiles-Group, a submitted test file, its verdict, and its PDF analysis report.
    • Builds on: Module 12. Simulation 12.1 follows files through WildFire at different license levels.
    • Sets up: the capstone's Corp-WF profile.

    03

    Walkthrough of the detailed steps

    2.1Load the lab configuration

    Every lab starts from a known baseline, so your firewall matches the guide no matter what you did last time.

    1. On the client desktop, log in as lab-user, open Firefox, and browse to https://192.168.1.254. Log in as admin with the password from Lab Settings. If the login page does not appear, wait 1 to 3 minutes for the firewall to finish booting and refresh.
    2. Go to and click Load named configuration snapshot. Choose edu-210-11.0a-10.xml and click OK, then Close.
    3. Open Tasks (lower right) and confirm the Load task shows completed.
    4. Click Commit (upper right), then Commit in the dialog, and wait for it to finish.

    Loading is not committing

    A loaded snapshot replaces only the candidate configuration. Until you commit, the firewall is still running whatever was there before, and nothing in the lab will match the guide.

    2.2Create a WildFire Analysis profile

    1. Go to and click Add.
    2. Name Corp-WF, description WildFire profile for Corp security rules.
    3. Click Add for a rule: name All_Files, Applications any, File Types any, Direction both, Analysis public-cloud. Click OK.

    Screenshot 1 The Corp-WF profile showing the All_Files rule sending any file type to public-cloud.

    2.3Isolate WildFire in the profile group

    1. Go to and open Corp-Profiles-Group.
    2. Set WildFire Analysis Profile to Corp-WF, and set every other profile to None. Click OK.

    Why turn the others off?

    With Antivirus or its inline machine learning active, the test file could be caught on the firewall before WildFire ever sees it. Turning them off lets you watch the cloud do its job alone. In production, all the profiles work together.

    A lab-only setting

    The next lab's baseline restores a normal group, so you don't need to undo this. But never leave a real firewall like this.

    2.4Update WildFire settings

    1. Go to and click the gear on General Settings.
    2. Check Report Benign Files and Report Grayware Files. Leave the rest. Click OK.
    3. In , open Allow-PANW-Apps. On Source, set Source Address to Any. Click OK.
    4. Commit.

    Why change Allow-PANW-Apps?

    The rule was limited to the firewall's management address. WildFire uploads and verdict lookups (paloalto-wildfire-cloud) need to match it reliably, so the lab widens the source.

    Benign and grayware reporting

    By default the WildFire Submissions log shows only malicious verdicts. These boxes make benign and grayware results visible too, which is useful when you're learning what gets sent.

    2.5Test the profile

    1. In a new Firefox tab, open http://192.168.50.80/wildfire-test-pe-file.exe and click Save when prompted. Close the tab.
    2. Open Remmina, double-click Firewall-A, and check the upload log. It may take a minute or two to show the file.
    Commandadmin@firewall-a> debug wildfire upload-log show
    1. Exit the SSH session.
    Commandadmin@firewall-a> exit

    Download the file, don't just open the link

    The firewall forwards files it sees transferred. Make sure Firefox actually saves it.

    Screenshot 2 The CLI showing wildfire-test-pe-file.exe in the upload log.

    2.6Examine the WildFire analysis

    1. Go to . Refresh until wildfire-test-pe-file.exe appears. Analysis can take 5 to 15 minutes; the log stays empty until there's a verdict.
    2. Click the magnifying glass on the entry to open the Detailed Log View and note the Verdict.
    3. Select the WildFire Analysis Report tab and click Download PDF.
    4. Scroll through the report. Section 3.1 describes the sandbox environment and what the file did.

    Use the wait

    Read Module 12's section on analysis reports while you wait. Don't reload the baseline or redo steps; that just restarts the clock.

    06

    How this looks on a real firewall

    • WildFire alongside everything else. Production groups include Antivirus, Anti-Spyware, Vulnerability, URL Filtering, and WildFire together. Inline machine learning stops many threats on the firewall in real time; WildFire covers what's left.
    • Get verdicts fast. With a WildFire license, new signatures arrive within minutes. Set the WildFire content update schedule to the shortest interval available.
    • Mind privacy and regulation. Some organizations can't send certain files to a public cloud. Options include a regional cloud, a private cloud appliance (WF-500), or excluding file types.
    • Decrypt to see files in HTTPS. Most downloads are encrypted. Without decryption (Lab 12), the firewall never sees the file to forward it.
    • Other vendors: Fortinet FortiSandbox, Cisco Secure Malware Analytics (Threat Grid), and Check Point SandBlast do the same job.
    07

    Check yourself

    Why can't Lab 8's antivirus profile stop a true zero-day file?

    It matches signatures, and a zero-day has no signature yet.

    Why does the lab set every other profile in the group to None?

    So nothing on the firewall stops the file before WildFire analyzes it.

    The WildFire Submissions log is empty right after the download. Is something wrong?

    Not necessarily. Entries appear only after a verdict, which can take 5 to 15 minutes.

    Which CLI command confirms the file was actually sent?

    debug wildfire upload-log show.

    What do Report Benign Files and Report Grayware Files change?

    They make benign and grayware verdicts appear in the WildFire Submissions log, not just malicious ones.
