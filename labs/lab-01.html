    01

    What this lab is for

    A new firewall out of the box can't do much. It doesn't know which DNS servers to ask, so it can't resolve updates.paloaltonetworks.com or download anything. Its clock may be wrong, which makes every log timestamp and every certificate check suspect. And its management interface will accept a login from anyone who can reach it. This lab fixes those three problems before the firewall carries a single packet of user traffic.

    You will also meet the habit that runs through every lab in the course: changes go into the candidate configuration when you click OK, and only become real when you commit.

    • You'll leave with: DNS and NTP configured, the domain and banner set, latitude and longitude entered, the management interface limited to the client network, and a software check run (without upgrading).
    • Builds on: Module 2, sections 2.1 to 2.5. Run Simulation 2.1 first; it shows exactly how a permitted-IP mistake locks you out.
    • Sets up: every later lab. Lab 2 starts from a baseline that already includes these settings.

    2.2Configure the DNS and NTP servers

    DNS lets the firewall turn names into addresses for updates, FQDN address objects, and logging. NTP keeps its clock honest.

    🧱On Firewall web interfacefirewall-a at https://192.168.1.254, in Firefox on the Client

    1. Select . Click the Services gear icon to open the Services window.
    2. In the Services window, verify that the Update Server is updates.paloaltonetworks.com. Set the Primary DNS Server to 8.8.8.8 and the Secondary DNS Server to 192.168.50.53.
    3. Select the NTP tab. Set the Primary NTP Server to 0.pool.ntp.org and the Secondary NTP Server to 1.pool.ntp.org. Click OK.
    4. Verify the settings have been updated in the Services panel: both DNS servers and both NTP server addresses.
    5. Leave the firewall open and continue to the next task.

    Why two DNS servers from different places

    8.8.8.8 is a public resolver on the internet; 192.168.50.53 is a lab DNS server in the extranet. If one path is down, the other still answers. In production you would normally point the firewall at your own internal resolvers first.

    Screenshot 2 The Services panel showing both DNS servers and both NTP servers.

    2.3Configure general settings

    🧱On Firewall web interfacefirewall-a at https://192.168.1.254, in Firefox on the Client

    1. Select . Click the gear icon on the General Settings panel to open the General Settings window.
    2. Verify the Hostname is firewall-a. For Domain, enter lab.local. For Login Banner, enter Authorized Access Only. Choose the Time Zone; the guide uses Etc/UTC, so use the same and your timestamps will match later screenshots. For Latitude enter 37.00 and for Longitude enter 122.00. Click OK.
    3. Leave the firewall open and continue to the next task.

    The guide says “Services gear icon”

    Step 1 of this task in the guide says to click the Services gear icon. On the Management tab, the panel you want is General Settings.

    Longitude has the wrong sign

    Longitudes west of Greenwich are negative. Santa Clara, California is about 37.35, -121.96. A positive 122.00 puts the firewall in eastern Asia on the ACC threat map. Enter the guide’s values (37.00 and 122.00) so your work matches the guide, but know the real answer.

    Screenshot 3 The General Settings panel showing the domain, banner, time zone, latitude, and longitude.

    2.4Modify the management interface

    🧱On Firewall web interfacefirewall-a at https://192.168.1.254, in Firefox on the Client

    1. Navigate to and click the interface name Management.
    2. In the Management Interface Settings window, verify 192.168.1.254 for the IP Address, 255.255.255.0 for the Netmask, and 192.168.1.10 for the Default Gateway. At the bottom of the Permitted IP Addresses area, click Add.
    3. In Permitted IP Addresses, type 192.168.1.20/24 for the IP Address and MGT access from this host only for the Description. Click OK.
    4. Leave the firewall open and continue to the next task.

    Two different gateways

    The high-level steps (Task 1.4) say the management gateway is 192.168.1.1. The detailed steps and the Lab Settings table say 192.168.1.10, the vRouter. Expect 192.168.1.10. This step is verify-only.

    “This host only” is not what a /24 does

    192.168.1.20/24 permits the whole 192.168.1.0/24 network, not just your client. To permit one host you would enter 192.168.1.20 or 192.168.1.20/32. Use the guide’s entry so you aren’t locked out, and notice the mismatch between the value and its description.

    Don’t lock yourself out

    Once the Permitted IP list has any entry, everything not on the list is refused. If you mistype the network and commit, your own browser session is cut off. If that happens, end the reservation and start the lab again.

    Settings reference

    What each setting in this lab does, and where it lives.

    SettingWhereWhat it does
    Primary and secondary DNSResolvers the firewall itself uses for updates, licensing, FQDN objects, and URL lookups. Not used by clients.
    Update serverWhere content and software updates come from. Leave the default.
    NTP servers (NTP tab)Time sources. Accurate time matters for logs, reports, certificates, and scheduled updates.
    Hostname and domain (General Settings)How the firewall names itself; appears in the CLI prompt and in logs sent elsewhere.
    Login banner (General Settings)Text shown before login. A legal notice that access is monitored and limited to authorized users.
    Latitude and longitude (General Settings)Places the firewall on the ACC and App Scope threat maps. Decimal degrees; west and south are negative.
    MGT IP, mask, gateway (Management)How you reach the web interface and SSH. The gateway lets management traffic reach other networks.
    Permitted IP addresses (Management)Allow list for management access. Empty means anyone who can route to it.
    Check NowLists PAN-OS versions available to download. It does not download or install.

    06

    How this looks on a real firewall

    • Keep management off user networks. In this lab the management port and your workstation share 192.168.1.0/24. In production, management sits on its own network or VLAN, reachable only from administrators' jump hosts.
    • Permit hosts or a small admin subnet, not a whole user network. The /24 in this lab would let any user try to log in. A real allow list names a few addresses.
    • Use internal DNS and NTP. Most organizations point the firewall at their own resolvers and time servers, which in turn reach the internet.
    • Write a real banner. Legal teams usually supply wording that states access is restricted and monitored.
    • Plan upgrades; don't click through them. Production upgrades follow a change window, a configuration backup (Lab 2), and the upgrade path Palo Alto Networks publishes for your version.
    • Other vendors work the same way. Fortinet, Cisco, and Check Point all have equivalent management-access lists, DNS and NTP settings, and banners. Only the menus differ.
    07

    Check yourself

    Answer in your head first, then open each one.

    You clicked OK on the DNS settings an hour ago. Is the firewall using them?

    Not unless you committed. OK writes to the candidate configuration; Commit makes it the running configuration.

    Why does Check Now fail on a brand-new firewall with no DNS configured?

    The update server is reached by name. With no resolver, the firewall can't turn updates.paloaltonetworks.com into an address.

    The guide's permitted IP entry is 192.168.1.20/24. Which clients can reach the management interface?

    Any host in 192.168.1.0/24, because the /24 makes it a network entry. Only 192.168.1.20/32 (or the bare address) would limit it to one host.

    Where would latitude 37.00, longitude 122.00 put the firewall on the threat map, and why?

    In eastern Asia. Positive longitude is east of Greenwich. Santa Clara is about -121.96.

    What is the difference between Check Now on the Software page and installing an upgrade?

    Check Now only lists available versions. Downloading and installing are separate, deliberate steps.
