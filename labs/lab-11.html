Lab 11: Controlling Access to Network Resources with User-ID

Write policy about people instead of addresses. You inspect an over-broad rule for a newly acquired company's zone, turn on User-ID for that zone, replace "allow everything" with an approved-apps rule, give only the marketing group its own applications, add an explicit deny, and confirm who was allowed what in the User-ID and Traffic logs.

    01

    What this lab is for

    IP addresses change; people and their roles don't. User-ID maps addresses to usernames and usernames to directory groups, so a rule can say "marketing may use these applications" and keep saying it as laptops move between networks.

    The story: your company has acquired another, whose users sit in a new Acquisition zone. Another admin left a rule allowing them any application to anywhere. You'll tighten it in three layers: approved apps for everyone, extra apps for the marketing group, and an explicit deny for the rest.

    • You'll leave with: User-ID enabled on Acquisition, Allow-Corp-Apps (renamed from Acquisition-Allow-All), Allow-Mktg-Apps for the marketing group, and Deny-All-Others at the bottom.
    • Builds on: Module 9. Simulation 9.2 (who gets what) mirrors this lab's results. You'll do this lab in week 5, before Labs 8 to 10, to match the module order.
    • Sets up: the Acquisition-zone rules that Labs 8, 13, and 14 assume.

    Why “any to any” is the problem

    That rule lets every acquired user reach every zone with every application, including your users’ network. It’s common after a merger, and it’s exactly what User-ID and App-ID together are meant to replace.

    2.7Create Deny rule

    Everything else from Acquisition is denied.

    🧱On Firewall web interfacefirewall-a at https://192.168.1.254, in Firefox on the Client

    1. Select . Click Add.
    2. General tab: Name Deny-All-Others. Description Denies non-approved applications for users in Acquisition zone.
    3. Source tab: click Add and select Acquisition. Leave Source User at any, so the rule applies to every user.
    4. Destination tab: use the drop-down at the top to select any.
    5. Application tab: verify Any is checked.
    6. Actions tab: change the Action to Deny. Click OK.
    7. Verify Deny-All-Others is at the bottom of your rules, just above intrazone-default. If not, use Move Down.
    8. Click the Commit link at the top-right of the web interface.
    9. In the Commit window, click Commit.
    10. When the commit completes, click Close.

    Why deny explicitly if interzone-default already does?

    Deny-All-Others states the intent, logs by default, and, because its destination zone is any, also catches Acquisition-to-Acquisition traffic that intrazone-default would otherwise allow.

    Order matters

    Above Allow-Mktg-Apps, the deny would shadow it. Last is the only correct place.

    The two halves of User-ID

    HalfAnswersComes from
    User mappingWhich user is at this IP?Server monitoring, agents, GlobalProtect, Authentication Portal, syslog, XML API
    Group mappingWhich groups is this user in?LDAP queries to the directory (a group mapping configuration)

    Useful CLI

    show user group list shows the groups the firewall has read from the directory. Follow it with show user group name and a group exactly as listed to see that group's members.

    Commandadmin@firewall-a> show user ip-user-mapping all
admin@firewall-a> show user group list

    06

    How this looks on a real firewall

    • Mapping is the hard part. In production, the firewall learns users from domain controller logs (server monitoring), GlobalProtect, or an identity provider. Every unmapped user falls into "any," so coverage matters.
    • Enable User-ID only on internal zones. Never on the internet-facing zone; it would try to identify untrusted sources.
    • Watch group mapping scope. Limit group mapping to the groups policy actually uses, so the firewall isn't reading the whole directory.
    • Mergers are a real use case. A separate zone for an acquired network, tightened with user and application rules, is a common integration pattern.
    • Other vendors: Fortinet FSSO, Cisco ISE with pxGrid, and Check Point Identity Awareness solve the same mapping problem.
    07

    Check yourself

    Why did the Source User column stay empty before task 2.4?

    The firewall only maps users in zones with User Identification enabled.

    Why use the group marketing instead of listing each marketing user?

    Membership is managed in the directory. New marketing users get access with no firewall change.

    What happens if Deny-All-Others is placed above Allow-Mktg-Apps?

    It shadows the marketing rule, and marketing users are denied too.

    What does Deny-All-Others catch that interzone-default wouldn't?

    Intrazone traffic within Acquisition, because its destination zone is any, and it logs by default.

    Why does the user filter need quotes?

    The username contains a backslash (chicago\sholmes), which must be quoted.
