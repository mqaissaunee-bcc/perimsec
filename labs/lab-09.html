Lab 9: Blocking Inappropriate Web Traffic with Advanced URL Filtering

Control the web two ways and compare them. You block risky URL categories with a Security rule, then with a URL Filtering profile that also logs everything allowed; add a custom category for specific sites and enforce it both ways; and finish by blocking a URL fed from an external dynamic list.

    01

    What this lab is for

    PAN-OS gives you two tools for web control, and this lab makes you use both on the same sites so the difference sticks:

    • A Security rule with URL categories as match criteria. It allows or denies whole sessions, and you see it in the Traffic log under the rule's name.
    • A URL Filtering profile attached to allow rules. It acts per category (block, alert, allow, continue, override), and with alert it records every site users visit, not just blocked ones.

    You'll also use a custom URL category for a short list of sites and an external dynamic list you can update without a commit.

    • You'll leave with: Block-Bad-URLs (category deny rule), Corp-URL-Profile in Corp-Profiles-Group, the Block-Per-Company-Policy custom category, and malicious-urls-edl.
    • Builds on: Module 11. Simulation 11.1 (what happens to this URL?) covers precedence between custom categories, EDLs, and PAN-DB.
    • Sets up: the capstone's Block_Bad_URLs rule and Corp-URL profile.

    Walkthrough of the detailed steps

    2.1Load the lab configuration

    Every lab starts from a known baseline, so your firewall matches the guide no matter what you did last time.

    1. On the client desktop, log in as lab-user, open Firefox, and browse to https://192.168.1.254. Log in as admin with the password from Lab Settings. If the login page does not appear, wait 1 to 3 minutes for the firewall to finish booting and refresh.
    2. Go to and click Load named configuration snapshot. Choose edu-210-11.0a-09.xml and click OK, then Close.
    3. Open Tasks (lower right) and confirm the Load task shows completed.
    4. Click Commit (upper right), then Commit in the dialog, and wait for it to finish.

    Loading is not committing

    A loaded snapshot replaces only the candidate configuration. Until you commit, the firewall is still running whatever was there before, and nothing in the lab will match the guide.

    2.2Clear logs and test two sites

    1. Double-click Clear Logs Firewall-A on the desktop, confirm the logs cleared, and press Enter.
    2. In Firefox, open http://www.hacker9.com (category hacking). It loads.
    3. Open http://www.hidester.com/proxy (category proxy-avoidance-and-anonymizers). It loads, redirecting to vpncentral.com. Close Firefox.

    Wrong task title

    The guide calls this "Generate Traffic Without Security Profiles." It actually clears the logs and confirms two sites aren't blocked yet.

    2.3Create a Security rule that blocks categories

    1. In , show the URL Category column if it's hidden (any column drop-down > Columns).
    2. Click Add. Name Block-Bad-URLs, description Blocks bad URLs based on categories.
    3. Source zone Users_Net; destination zone Internet; Application Any.
    4. Service/URL Category: Service application-default. Add these categories: adult, command-and-control, extremism, hacking, high-risk, malware, nudity, parked, peer-to-peer, phishing, proxy-avoidance-and-anonymizers, questionable.
    5. Actions: Deny, Log at Session End checked. Click OK.
    6. Select the rule and choose Move > Move Top. Commit.

    Name drift

    Step 9 calls the rule "block-known-bad-urls." It's Block-Bad-URLs.

    Move Top puts it above the known-bad address rules

    That's fine for this lab. What matters is that it's above Users_to_Internet; below it, the deny would be shadowed.

    Screenshot 1 The rulebase with Block-Bad-URLs at the top and its URL categories visible.

    2.4Test the category deny rule

    1. Open a private Firefox window. Browse to http://www.hacker9.com. You get a block page saying web-browsing was blocked.
    2. Browse to http://www.hidester.com/proxy. Same kind of page. Close Firefox.
    3. Go to and find the blocked entries.

    "Application web-browsing blocked"?

    The page is the generic application block page, because a Security rule denied the session. The category is why the rule matched. A URL Filtering profile shows a different page that names the category, as you'll see in 2.10.

    Screenshot 2 The block page for hacker9.com produced by the Block-Bad-URLs rule.

    Screenshot 3 The URL Filtering log showing the blocked hacker9 and hidester entries.

    2.5Create a URL Filtering profile

    1. Go to and click Add. Name Corp-URL-Profile, description Company URL Filtering profile.
    2. Click the small triangle on the Site Access column header and choose Set All Actions > alert.
    3. Set block for: adult, command-and-control, copyright-infringement, extremism, hacking, high-risk, malware, nudity, parked, peer-to-peer, phishing, proxy-avoidance-and-anonymizers, questionable, unknown. Click OK.

    alert versus allow

    Both let the user through. alert writes a URL Filtering log entry; allow doesn't. Setting everything to alert first is what makes the profile a record of all web activity.

    Two more categories than the rule

    The profile adds copyright-infringement and unknown. The guide's screenshot only shows four categories set; set all fourteen.

    2.6Add the profile to the group and disable the rule

    1. Go to , open Corp-Profiles-Group, set URL Filtering Profile to Corp-URL-Profile, and click OK.
    2. In , select Block-Bad-URLs and click Disable. It turns italic.
    3. Commit.

    Name drift

    The guide's heading calls the profile "Corp-URL-Filtering." Select the Corp-URL-Profile you created.

    2.7Create a custom URL category

    1. In a private window, open http://www.nbcnews.com. It loads. Close Firefox.
    2. Go to and click Add. Cancel the trailing-slash notice.
    3. Name Block-Per-Company-Policy, description URLs that are blocked by company policy., Type URL List. Add *.nbcnews.com and *.theguardian.com. Click OK.
    4. Open Block-Bad-URLs, and on Service/URL Category add Block-Per-Company-Policy. Click OK.
    5. Select Block-Bad-URLs and click Enable. Commit.

    Wildcard syntax

    *.nbcnews.com matches www.nbcnews.com and other subdomains. Enter the entries exactly as shown.

    2.8Test the custom category in the Security rule

    1. In a private window, browse to www.nbcnews.com and www.theguardian.com. Both show the application block page. Close Firefox.

    2.9Add the custom category to the profile

    1. Open Corp-URL-Profile. Under Custom URL Categories, set Block-Per-Company-Policy's Site Access to block. Click OK.
    2. Select Block-Bad-URLs and click Disable. Commit.

    2.10Test the custom category in the profile

    1. In a private window, browse to www.nbcnews.com and www.theguardian.com. This time you get Web Page Blocked, the URL Filtering block page, which names the category.
    2. Close Firefox.

    Screenshot 6 The Web Page Blocked page from the URL Filtering profile, showing the category.

    2.11Create an EDL of malicious URLs

    1. Go to and click Add. Cancel the notice.
    2. Name malicious-urls-edl, Type URL List, description List of malicious URLs maintained on Extranet server, Source http://192.168.50.80/malicious-urls.txt, Check for updates Every Five Minutes. Click OK.
    3. Reopen it, cancel the notice, and click Test Source URL. Close, then OK.

    What's on the list

    One test URL: www.popurls.com.

    2.12Block the EDL with the Security rule

    1. Open Block-Bad-URLs. On Service/URL Category, add malicious-urls-edl. Click OK.
    2. Select the rule and click Enable. Commit.

    2.13Test the EDL

    1. In a private window, browse to www.popurls.com. You get the application block page. Close Firefox.
    2. In the URL Filtering log, clear filters and apply ( action eq block-url ). You see the popurls entries.

    Why an EDL beats editing the rule

    The firewall rereads the list every five minutes. Add a URL to the file on the server and it's blocked soon after, with no commit.

    Rule match versus profile

    Security rule with URL categoriesURL Filtering profile
    Acts onWhole session: allow or denyEach URL, per category action
    LogsTraffic log under the rule name, plus URL log for blocksURL Filtering log for alert, block, continue, override
    User seesApplication block pageWeb Page Blocked page with the category
    Best forHard blocks of a few categoriesVisibility and nuanced actions on everything

    Profile actions

    ActionUserLogged
    allowAllowedNo
    alertAllowedYes
    blockBlockedYes
    continueWarning page, may proceedYes
    overrideNeeds a password to proceedYes

    Precedence when a URL matches several things

    Custom categories and EDLs are checked before PAN-DB categories. If a URL is in more than one category with different actions, the most restrictive action wins (Module 11).

    06

    How this looks on a real firewall

    • Profiles do most of the work. Most organizations attach a URL Filtering profile to every internet allow rule and use category deny rules sparingly.
    • Alert on everything. Logging all categories is what lets you answer "who visited this site?" during an incident.
    • Block unknown and newly-registered domains. Many attacks use brand-new domains; blocking or warning on those categories is a common recommendation.
    • HTTPS needs decryption for full detail. Without decryption, the firewall still sees the hostname (SNI) and can categorize it, but it can't see full URL paths or show block pages cleanly. Lab 12 adds decryption.
    • Other vendors: Fortinet FortiGuard web filtering, Cisco Talos URL categories, and Check Point URL Filtering follow the same profile model.
    07

    Check yourself

    Both a deny rule and a profile can block hacker9.com. What does the profile give you that the rule doesn't?

    Per-category actions and a log of every allowed site (with alert), plus a block page that names the category.

    Why disable Block-Bad-URLs before testing the profile?

    Otherwise the rule blocks first and you never test the profile.

    What's the difference between allow and alert in a URL Filtering profile?

    Both let the user through; alert also writes a URL Filtering log entry.

    You add a URL to the file behind malicious-urls-edl. Do you need to commit?

    No. The firewall rereads the list on its schedule (every five minutes here).

    Does *.nbcnews.com match www.nbcnews.com?

    Yes. The wildcard covers its subdomains.
