Logs and Reports

Everything you've configured has been writing records: every session, threat, URL, file, and verdict. This module is about turning those records into answers, quickly enough to matter, and getting them off the firewall to the people and systems that need them.

By the end of this module you should be able to

  1. Use Dashboard widgets for an at-a-glance view of threats and applications.
  2. Investigate traffic and threats with the ACC's tabs, widgets, and global filters.
  3. Explain what each log type records and what controls whether it's written, and filter logs precisely.
  4. Use the correlation engine, App Scope, and predefined reports.
  5. Build and schedule custom reports with the query builder.
  6. Forward logs to syslog, SNMP, email, HTTP, Panorama, or Strata Logging Service using server profiles and log forwarding profiles.

    14.1

    The Dashboard

    The first screen after login: a glance, not an investigation.

    The Dashboard is a set of widgets, each a pane showing one kind of information. Add widgets from the Widgets menu, remove them, and drag them to rearrange. Your layout is saved per administrator.

    • Threat widgets: Threat Logs, URL Filtering Logs, and Data Filtering Logs show the last 10 entries from the last hour.
    • Application widgets: Top Applications and Top High Risk Applications show what's on the network, colored by Palo Alto Networks risk rating (4 in orange, 5 in red). Point to an application for details; click it to open the ACC filtered to that application.
    • System widgets such as General Information (model, PAN-OS and content versions, uptime), System Resources, and Logged In Admins.
    14.2

    The Application Command Center

    Interactive analysis: start broad, click to narrow.

    The ACC organizes widgets into tabs. Network Activity and Threat Activity are used most; Blocked Activity shows what the firewall prevented, which is useful when someone asks what the firewall is actually doing. You can add tabs of your own.

    Mostly applications and trafficMostly threats
    Application Usage, User Activity, Source IP Activity, Destination IP Activity, Source and Destination Regions, GlobalProtect Host Information, Rule Usage Threat Activity, WildFire Activity by File Type and by Application, Hosts Visiting Malicious URLs, Hosts Resolving Malicious Domains, Applications Visiting Non-Standard Ports, Rules Allowing Apps on Non-Standard Ports, Compromised Hosts

    Each widget has a graph and a table. You can sort it, switch between sessions, bytes, and threats, and use Jump to Logs to open the matching log entries with the filter already built. The key tool is the global filter: hover over a value in any widget table (an application, user, or severity) and click the arrow to promote it. The filter then applies to every widget on every tab, so "web-browsing" on Network Activity also narrows Threat Activity. Set the time range at the top, and clear global filters when you're done.

    Think of it this way

    The ACC is a funnel. Start with everything from the last week, drop in one application, then one user, then one threat, and each step narrows every view at once.

    14.3

    Logs and log filters

    The detailed record, and how to find one line in a million.

    A log is a timestamped list of events, one per row, with columns of detail you can show, hide, and rearrange. Whether an entry is written at all depends on your configuration:

    LogRecordsWritten when
    TrafficOne entry per session: zones, addresses, user, application, rule, action, bytes, session end reasonThe Security rule logs at session start or end (end recommended). In-progress sessions don't appear with log at end.
    ThreatThreats in allowed traffic: name, severity, actionAntivirus, Anti-Spyware, or Vulnerability Protection profiles detect something.
    URL FilteringURLs, categories, actionsA URL Filtering profile action of at least alert applies.
    WildFire SubmissionsAnalyzed files and links: sender, receiver, file name, verdictA WildFire Analysis profile forwards a file (benign and grayware only if reporting is enabled).
    Data FilteringBlocked or alerted files and sensitive dataFile Blocking or Data Filtering profile with at least alert.
    Decryption, User-ID, System, Configuration, and othersTheir own eventsCovered in earlier modules.

    The Unified log at combines several log types in one view, which helps when following an incident across traffic, threats, URLs, and WildFire. For the Threat log, a reasonable baseline is that critical and high-severity threats should always be blocked, medium threats often should be, and low and informational threats should at least alert.

    Filters

    You have built filters in nearly every lab. The pattern is always ( field operator value ), joined with and or or. Click a value in a log to add it, or use the Add Log Filter button (the Filter Builder) to pick fields and operators from lists. Values with spaces or backslashes go in single quotes.

    ( severity geq high )
( user.src eq 'chicago\escrooge' )
( zone.src eq Users_Net ) and ( app eq web-browsing )
( flags has proxy ) and ( session_end_reason eq threat )
( addr.dst in 192.168.1.80 )

    The correlation engine
    

    The correlation engine looks across logs for patterns defined in correlation objects, which Palo Alto Networks' threat research team writes and delivers in content updates. Each object defines a pattern, the logs to examine, and a time window, such as a host that downloads an executable, then visits a malware URL, then beacons to a C2 domain. Matches become correlated events: notices of a probably compromised host, shown in the ACC's Compromised Hosts widget and under Monitor.

    14.4
    App Scope and predefined reports
    

    Trends over time, and reports you don't have to build.
    

    App Scope
    

    App Scope, under Monitor, shows changes in application and user activity, bandwidth hogs, and threats:
    

      

    • Summary: six charts in one pane, including the top 5 gainers and losers (biggest change in sessions over the last hour), top bandwidth sources, applications, and categories, and top threats.
      • 

    • Change Monitor: applications, users, sources, and destinations with the largest increase in sessions over a period you choose.
      • 

    • Threat Monitor: threats in the most sessions, by name, category, source, or destination.
      • 

    • Threat Map and Traffic Map: threats and traffic on a world map by country.
      • 

    • Network Monitor: the largest bandwidth consumers by application, user, source, and destination.
      • 

    

    Predefined reports
    

    At , more than 40 predefined reports are grouped into categories such as Application, Traffic, Threat, and URL Filtering. The firewall generates a new set every day from summary databases that are updated in 15-minute intervals. Pick a report, pick a date in the calendar (gray dates have no data), view it in the browser, or download a PDF.
    

    


    

    14.5
    Custom reports
    

    Exactly the columns, filters, and schedule you need.
    

    At , add a report and choose:
    

      

    • Database: a summary database (such as Traffic Summary or Threat Summary) for fast reports over long periods, or a detailed log for line-level detail.
      • 

    • Time frame, Sort By (for example sessions, top 100), and Group By (for example source zone, 5 groups).
      • 

    • Selected columns, in the order they should appear.
      • 

    • Query Builder: a filter in the same syntax as the logs, so only matching entries are included. For example, "category of application equals networking" lists every networking application seen, useful for tightening perimeter rules.
      • 

    • Scheduled: run it automatically each day.
      • 

    

    Run Now shows the result immediately. Reports can be exported as PDF, CSV, or XML, and report groups can be emailed on a schedule.

    14.6
    Log forwarding
    

    A firewall's disk is small and its logs are evidence. Send them somewhere safe.
    

    Forwarding gives you off-firewall backup, centralized analysis across many firewalls, longer retention, alerts for critical events, and automated responses. Destinations include Panorama, Palo Alto Networks' cloud logging service (Strata Logging Service, formerly Cortex Data Lake), syslog servers and SIEMs, SNMP managers (traps), email servers, and HTTP servers, which can trigger actions in other systems through their APIs.
    

    Three steps
    

      

    1. Server profile at , for example Syslog: the server's address, transport and port, format, and facility. It defines where and how to connect.
      2. 

    2. Log Forwarding profile at : for each log type, a filter (All Logs means no filtering) and the server profiles to send matching entries to. It defines what to send where.
      3. 

    3. Apply it: on each Security rule's Actions tab, select the Log Forwarding profile. Threats found by Zone Protection profiles are forwarded through a setting on the zone itself at Network > Zones. System, configuration, and other device logs are forwarded under .
      4. 

    

    In the field
    

    Like Security Profile Groups, a Log Forwarding profile named default is applied automatically to new rules. Create one early so every rule forwards from the day it's written.

    Watch out for
    

    • Let the script run first. Widgets, the ACC, and App Scope need data. If something is empty, wait a few minutes and refresh.
    • Global filters stick. An ACC global filter applies to every widget and tab until you clear it. If numbers look oddly small, check the Global Filters area.
    • Gray dates in reports. Predefined reports are generated daily, so a lab environment may have data on only some days. Click through dates until you find one with data, as the guide says.
    • Clear log filters between tasks. Each step expects to start from an empty filter. Leftover filters are the most common reason a step shows nothing.
    • The source user filter has a backslash. chicago\escrooge includes the domain. If you type the filter by hand rather than building it, it needs quotes: ( user.src eq 'chicago\escrooge' ).
    • Read the custom report carefully. It's filtered to exclude traffic sourced from the Internet zone, and the guide notes what that leaves. Ask yourself why each zone does or doesn't appear.
