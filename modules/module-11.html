Advanced URL Filtering

Most attacks arrive on the web: a phishing link, a malicious download, a freshly registered domain hosting an exploit kit. URL filtering cuts off the dangerous neighborhoods before a user ever gets there, and gives you control over the merely inappropriate ones too.

    Part A

    How URL filtering works

    Categories, PAN-DB, and two places to use them.

    11.1

    Why filter URLs, and how sites get categories

    Block the delivery and the phone call home.

    Web traffic is hard to secure. The business needs the web, much of it is encrypted, and in many organizations web proxies, firewalls, and endpoint tools are run by different teams. URL filtering on the firewall attacks two stages of the cyberattack lifecycle directly: delivery (the phishing page, the malicious download site) and command-and-control (the site malware reaches out to).

    PAN-DB

    PAN-DB is Palo Alto Networks' cloud URL database. It groups websites into categories by content and purpose, such as news, shopping, or social-networking, and by risk, such as malware, phishing, command-and-control, and high-risk. With Advanced URL Filtering, a site can belong to several categories at once, typically one for content and one for risk: a recently compromised news site might be both news and high-risk. Sites registered fewer than 32 days ago are placed in newly-registered-domain, a favorite of attackers.

    The firewall keeps a cache of recent lookups and asks the cloud about URLs it hasn't seen. Advanced URL Filtering also analyzes pages inline, in real time, to catch new phishing and malicious sites that aren't categorized yet. Custom categories you define need no license; PAN-DB categories require the URL filtering subscription.

    Think of it this way

    PAN-DB is a city map with neighborhoods shaded by purpose and by crime rate. Your URL policy decides which neighborhoods employees may visit, which they visit with a warning, and which are off the map.

    Building URL filtering

    11.3

    The URL Filtering profile

    Every category, two decisions, and two special cases.

    At , the predefined default profile is read-only, with malicious categories already set to block. Clone it or add a new profile. The Categories tab lists every category, your custom categories, and URL EDLs, each with two settings:

    • Site Access: what happens when a user opens a URL in that category. allow (the default for most categories; not logged), alert (allowed and logged), continue (a warning page with a Continue button), override (a password is required to proceed), or block.
    • User Credential Submission: what happens if a user tries to submit corporate credentials to a site in that category, a key defense against credential phishing.

    The column header has a drop-down to change every category's action at once, which is how you set "alert on everything" before carving out blocks.

    Two categories that aren't really categories

    • unknown: PAN-DB had no record of the URL. Brand-new sites land here, and so do some malicious ones. Set the action to fit your risk tolerance; many organizations block or continue.
    • not-resolved: the firewall couldn't reach PAN-DB to ask. The recommendation is alert, so that a cloud outage doesn't block all web traffic.

    Best-practice starting point

    Block command-and-control, dynamic-dns, hacking, high-risk, malware, phishing, and unknown. Consider blocking adult, extremism, newly-registered-domain, parked, proxy-avoidance-and-anonymizers, and questionable. Set the rest to alert rather than allow, so every category is logged and visible in reports.

    Common misconception

    "allow and alert are the same, since the user gets through either way." Only alert writes a URL Filtering log entry. With allow you have no record of where users went.

    11.4

    Custom categories, URL lists, and precedence

    Your own lists come first.

    A custom URL category at is either a list of URLs (wildcards allowed, such as *.example.com) or a combination of predefined categories, such as "shopping and auctions." A URL external dynamic list is a list hosted on a web server that the firewall checks for updates on a schedule. Both can be used as a rule's URL category or given an action in a URL Filtering profile.

    Lookup order

    1. Custom URL categories
    2. External dynamic lists
    3. The PAN-DB cache on the firewall
    4. The PAN-DB cloud

    When a URL matches a custom category, that category's action takes precedence over the predefined categories the URL also belongs to. When a URL has several predefined categories with different actions, the most severe action applies: block, then override, then continue, then alert, then allow.

    That precedence makes exceptions easy. To let penetration testers reach the hacking category except one particular site, allow the hacking category for them and put the one site in a custom category set to block.

      11.5

      Response pages, override, and other options

      What users see, and a few powerful extras.

      • Response pages at : the URL Filtering and Category Match block page, the continue and override page, and others can be customized with your organization's wording. Data interfaces that serve them need an Interface Management Profile with Response Pages enabled (Module 5).
      • Admin override: for the override action, set the password and how long access lasts at .
      • Safe search enforcement, on the profile's Settings tab, blocks searches that don't use the search engine's strict safe-search setting.
      • Logging options: log the container page only (the default, which keeps logs readable), and optionally record user agent, referer, and X-Forwarded-For headers.
      • HTTP header insertion adds or overwrites headers in requests. Predefined types for Dropbox, Google, Office 365, and YouTube let you restrict users to your organization's enterprise accounts. A dynamic field can insert the user's name for a downstream device.
      • Recategorization: if PAN-DB has a site wrong, request a change from the URL Filtering log entry or Palo Alto Networks' Test A Site page.

      Watch out for

      • Object names drift in the guide. The group is called Corp-Profiles-Group in the headings and the detailed steps, but Corp-Security-Group in one high-level step. The profile is Corp-URL-Profile when you create it and Corp-URL-Filtering when you add it to the group. They are the same objects; select what you actually created.
      • Keep track of the rule's state. Block-Bad-URLs is enabled, disabled, and re-enabled several times. Before each test, check whether it is supposed to be on; if it's on, it blocks first and you won't be testing the profile at all.
      • Two different block pages. A deny rule matching on URL category produces a generic application-style block. A profile's block action shows the URL Filtering block page with the category. Noticing the difference is part of the lab.
      • Wildcard syntax. *.nbcnews.com matches www.nbcnews.com and other subdomains. Enter the entries exactly as the guide shows them.
      • Read both logs after each test. A deny rule matching on URL category logs the session in the Traffic log under the rule's name and records the category in the URL Filtering log. A profile records each URL with its category and the profile's action, such as alert or block-url.

      Summary and self-check

      • URL filtering disrupts the delivery and command-and-control stages of attacks. PAN-DB assigns sites to content and risk categories, including newly-registered-domain; Advanced URL Filtering adds inline analysis.
      • URL categories can be Security rule match criteria (the rule's action applies) or entries in a URL Filtering profile attached to allow rules (per-category actions and detailed logging).
      • Profile actions: allow (not logged), alert, continue, override, block. User Credential Submission controls credential entry per category. Set not-resolved to alert; decide deliberately on unknown.
      • Lookup order: custom categories, EDLs, cache, cloud. Custom categories take precedence; among multiple predefined categories the most severe action wins.
      • Response pages, admin override, safe search, header insertion, and recategorization requests round out the feature.

      Key terms

      PAN-DB, URL Filtering profile, custom URL category, external dynamic list, credential phishing.
