    Part A

    Why and what

    What problem a next-generation firewall solves, and the products built to solve it.

    1.1

    Why "next-generation"?

    A traditional firewall asks two questions: where is this packet going, and on which port? For years that was enough.

    Port-based firewalls assumed each application used a known port: web on 80, mail on 25, DNS on 53. Allow the port and you allowed the application. That assumption broke a long time ago. Today almost everything rides on TCP 443: email, file sharing, chat, video, remote access tools, and malware command-and-control. Many applications hop to whatever port is open, tunnel inside other protocols, or encrypt everything. A rule that says "allow 443" says almost nothing about what is actually being allowed.

    A next-generation firewall makes decisions on three things a port number cannot tell you:

    • Which application this is, whatever port it uses (App-ID).
    • Which user sent it, not just which IP address (User-ID).
    • What the content contains: exploits, malware, dangerous URLs, or sensitive data (Content-ID).

    Think of it this way

    A port-based firewall is a building guard who only checks which door you came through. A next-generation firewall checks your badge (who you are), the reason for your visit (what application), and your bag (what you are carrying), then decides whether the door matters at all.

    Four goals that shape the whole course

    Palo Alto Networks describes its approach as four goals that build on each other. You will see each one become a set of features in later modules.

    GoalWhat it meansWhere you build it
    Complete visibilitySee every application, user, and piece of content, including encrypted traffic.App-ID, User-ID, decryption, logs (Modules 8, 9, 13, 14)
    Reduce the attack surfaceAllow only what the business needs; block everything else by default.Zones, Security policy, URL filtering (Modules 5, 6, 11)
    Prevent known threatsBlock exploits, malware, and command-and-control already identified by signatures.Security Profiles (Module 10)
    Prevent unknown threatsAnalyze never-seen-before files and links and turn the results into new protections.WildFire (Module 12)

    The order matters. You cannot reduce what you cannot see, and every threat you stop with a signature is one fewer that has to be caught by slower analysis.

    Common misconception

    "If I block the right ports, unwanted applications can't get in." Evasive applications deliberately use ports you already allow. Blocking port 6881 does nothing to a BitTorrent client that has moved to port 443. Identifying the application is the only reliable way to control it.

    The firewall you configure in this course is one member of a family that shares the same operating system, policy model, and security services.

    ProductWhat it isTypical use
    Next-generation firewall (PA-Series)Physical appliances running PAN-OS.Branch offices, campus perimeters, data centers.
    VM-SeriesThe same firewall as a virtual machine.Private data centers and public clouds such as AWS, Azure, and Google Cloud.

    PanoramaCentral management and logging.Organizations running more than a handful of firewalls.
    Prisma AccessThe firewall's security delivered as a cloud service.Remote users and branch sites without local appliances (Module 15).

    Because every form factor runs the same policy model, what you learn on the lab firewall transfers directly. A Security policy rule, a NAT rule, or an antivirus profile looks the same on a branch appliance, a VM in Azure, or a Panorama template.

    Exam tip

    Panorama manages firewalls and collects their logs. It does not inspect traffic itself. If a question asks which product enforces policy on packets, Panorama is never the answer.

    1.3

    Single-pass architecture

    How the firewall does all that inspection without slowing traffic to a crawl.

    The older way to add security was to stack devices: a firewall, then an intrusion prevention system, then an antivirus gateway, then a web proxy. Each device reassembles the traffic, parses it, scans it, and passes it on. Each has its own policy, its own logs, and its own administrators. Every added service adds another full pass over the same bytes, and the policies inevitably drift apart.

    A single-pass architecture processes each packet once:

    1. Classify the traffic: which application is it? (App-ID)
    2. Map it to a user and group. (User-ID)
    3. Scan the content for threats, URLs, and sensitive data, all in one stream using one signature format. (Content-ID)
    4. Enforce one unified policy that can use all of the above at once.

    Two design choices make this fast. First, stream-based scanning: signatures are matched as data flows through, instead of buffering an entire file before scanning it. Second, parallel processing: dedicated hardware handles networking, security processing, and signature matching side by side, which is the subject of Section 1.4.

    Part B

    Inside the firewall and where it runs

    The hardware split that keeps management responsive, the security model the platform is built for, and the form factors you can deploy.

    1.4

    Control plane and data plane

    A Palo Alto Networks firewall is really two computers in one chassis.

    The control plane manages the firewall. It has its own processor, memory, and disk, and it handles configuration, logging, and reporting. The dedicated management port and the console port connect here.

    The data plane moves and inspects traffic. On hardware models it is divided into three groups of specialized components:

    Data plane layerJobs
    Network processingFlow control, route lookup, MAC lookup, QoS, NAT
    Security processingApp-ID, User-ID, URL matching, policy matching, SSL and IPsec decryption, decompression
    Signature matchingVulnerability exploits, viruses, spyware, and data patterns such as credit card and Social Security numbers

    Why separate them? Because a firewall under attack still has to be manageable. If a flood of traffic saturates the data plane, the control plane keeps its own resources, so you can still log in through the management port, read the logs, and change policy. The reverse is also true: generating a large report on the control plane does not steal cycles from packet processing.

    Think of it this way

    An air traffic control tower and the runways. The runways (data plane) move the aircraft; the tower (control plane) plans, records, and directs. A traffic jam on the runways does not stop the tower radios from working.

    1.5

    Zero Trust

    The security model the platform is designed to support: never trust, always verify.

    The classic perimeter model treated the network like a castle. Anything outside the wall was untrusted; anything inside was trusted. Once an attacker got in, through a phishing email, a stolen VPN credential, or an infected laptop, they could move from system to system with little resistance. That lateral movement is how a single compromised workstation becomes a breach of the payroll database.

    Zero Trust removes the idea of a trusted inside. Being on the internal network earns nothing. Every flow is identified, checked against least-privilege policy, and inspected, in two directions:

    • North-south: traffic entering or leaving the organization, between users or servers and the internet.
    • East-west: traffic between internal segments, for example from the user network to the application servers.

    The firewall supports this with the tools you will build over the next weeks: security zones that divide the network (Module 5), Security policy that allows only specific applications for specific users between those zones (Modules 6, 8, 9), and inspection of everything allowed (Modules 10 to 13).

    Think of it this way

    A hotel where your keycard opens your room, the gym, and the lobby, and nothing else. The front door is not where security ends. Each door checks again.

    1.6

    Form factors and virtual systems

    Same policy model, different packaging.

    PA-Series appliances

    Hardware firewalls come in families sized for the job: small desktop units for branches and remote offices, mid-range appliances for the network perimeter, high-capacity models for large data centers, and modular chassis at the very top. In the generation covered by the EDU-210 materials, the PA-400 family serves small branches, the PA-3400 family the perimeter, the PA-5400 family large data centers, and the PA-7000 chassis the largest environments. Model numbers change every few years, so treat the current datasheet as the source of truth; what matters is matching throughput with threat prevention turned on, not raw firewall throughput, to the site.

    VM-Series

    The VM-Series delivers the same features as a hardware firewall in a virtual machine, for private virtualized data centers and public clouds. Capacity scales with the virtual CPUs and memory you give it. In Palo Alto Networks' published examples, doubling the vCPU count roughly doubles throughput and new sessions per second, and threat prevention throughput runs at about half of App-ID-only throughput. Your NDG lab firewall is almost certainly a VM-Series.

    CN-Series

    The CN-Series runs as containers inside a Kubernetes cluster. It brings Layer 7 visibility, application-level segmentation, and threat prevention to traffic between microservices that never touch a traditional network segment.

    Prisma Access

    Prisma Access delivers the firewall's security as a cloud service. Remote users and branch sites connect to the nearest cloud location instead of hauling traffic back to headquarters. You will study it as part of SASE in Module 15.

    Virtual systems

    A virtual system (vsys) is a separate logical firewall inside one physical firewall. Each vsys has its own interfaces, zones, policies, and administrators, which creates an administrative boundary. Typical uses are a service provider hosting several customers on one appliance, or a company giving separate departments their own firewall without buying separate hardware. Larger models support multiple virtual systems; some require a license for additional ones.

    Exam tip

    A virtual system is a whole separate firewall instance with its own policy and administrators. A virtual router (Module 5) is only a routing table. Questions often put both in the answer choices.

    Summary and self-check

    • Port numbers no longer identify applications. A next-generation firewall decides by application (App-ID), user (User-ID), and content (Content-ID).
    • The approach builds in four steps: complete visibility, a reduced attack surface, prevention of known threats, and prevention of unknown threats.
    • The portfolio shares one OS and policy model: PA-Series, VM-Series, CN-Series, cloud-delivered security services, Panorama for management, and Prisma Access in the cloud.
    • Single-pass architecture parses traffic once, scans it as a stream with one signature format, and enforces one policy, with parallel hardware doing the work.
    • The control plane (management, configuration, logging, reporting) and data plane (network processing, security processing, signature matching) have separate resources, so a traffic flood does not lock out administrators.
    • Zero Trust grants no trust for being inside: inspect north-south and east-west traffic with least-privilege policy.
    • A virtual system is a separate logical firewall within one physical firewall.
