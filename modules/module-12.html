    Part A

    How WildFire works

    From unknown file to worldwide protection.

    12.1

    The WildFire cycle

    Every subscribed firewall is a sensor, and every discovery protects all of them.

    WildFire is Palo Alto Networks' cloud-based malware analysis service. Firewalls around the world forward unknown files and links to it; analysts and other products can also submit samples by hand or through the API. WildFire decides what each sample is, and when it finds malware it generates protections and distributes them to every subscribed firewall.

    What happens to a file

    1. A file crosses an allow rule that has a WildFire Analysis profile attached. The firewall calculates the file's hash.
    2. If the file is signed by a trusted signer, or exceeds the configured size limit for its type, it is not forwarded.
    3. The firewall asks whether WildFire has seen this hash. If so, it already has a verdict: benign or grayware files are allowed; malware and phishing are blocked (using the signature already delivered).
    4. If not, the firewall forwards the file. WildFire analyzes it with static analysis, machine learning, and dynamic analysis, actually running it in a sandbox on several operating systems to watch what it does.
    5. WildFire records a verdict and informs the firewall. For malware it generates a signature, sends it to firewalls (in near real time with a subscription, or in the daily Antivirus content otherwise), and updates the malware and phishing categories in PAN-DB.

    Analysis takes minutes, so the very first copy of a brand-new file is normally delivered while it is being analyzed. Every copy after the signature arrives is blocked. That is why the Antivirus profile's WildFire inline ML (Module 10) matters: it can stop many first copies on the spot.

    WildFire also analyzes links. Email links and attachments seen by the firewall can be submitted, and malicious URLs it finds feed PAN-DB, so URL Filtering (Module 11) starts blocking them too.

      12.2

      Verdicts, licenses, and deployments

      Four verdicts, three tiers, and a choice of where analysis happens.

      The four verdicts

      VerdictMeaning
      BenignSafe; shows no malicious behavior.
      GraywareNot a security threat, but obtrusive or unwanted: adware, some spyware, browser helper objects.
      Malicious (malware)Malicious in nature and intent: viruses, worms, trojans, remote access tools, rootkits, botnets.
      PhishingA link or page that tries to trick users into revealing credentials, judged by its properties and behavior.

      Licensing

      • Without a WildFire subscription, the firewall still forwards Windows PE files (EXE, DLL, SCR, and similar) automatically, and WildFire analyzes them across Windows, macOS, Android, and Linux environments. Resulting signatures arrive in the daily Antivirus update, typically 24 to 48 hours later, which requires a Threat Prevention license.
      • A WildFire subscription adds many more file types (Microsoft Office, PDF, Java, archives such as RAR and 7-Zip, Linux ELF, Android APK, macOS Mach-O, DMG, and PKG, and scripts such as JavaScript, VBScript, and PowerShell), real-time WildFire signature updates, and manual submission through the API.
      • Advanced WildFire adds analysis built for evasive malware: a custom hypervisor that observes malware from outside the virtual machine, intelligent run-time memory analysis, automated unpacking, malware family fingerprinting, dependency emulation, and configuration file analysis.

      Where analysis happens

      • Public cloud: Palo Alto Networks' global or regional WildFire clouds. The default.
      • Private cloud: a WF-500 or WF-600 appliance on your own network, for organizations that can't send files off-site.
      • Hybrid: send common file types such as PE and APK to the public cloud and sensitive documents to the private appliance, choosing per WildFire Analysis profile rule.

      12.3

      Configuring WildFire

      Three places: firewall settings, the profile, and the update schedule.

      Firewall settings

      At :

      • WildFire cloud: which public cloud to use, and private cloud settings if you have an appliance.
      • File size limits per file type. Files larger than the limit aren't forwarded.
      • Report Benign Files and Report Grayware Files: by default only malicious and phishing results appear in the WildFire Submissions log. Turn these on to see everything that was analyzed.
      • Session information settings: which details (source and destination addresses, ports, users, URLs, and so on) accompany each submission and appear in reports.

      One related setting lives on a different tab. Allow forwarding of decrypted content, at , is off by default: files extracted from decrypted SSL traffic (Module 13) aren't sent to WildFire until you enable it.

      The WildFire Analysis profile

      At , the predefined default profile sends every file type, for any application, in both directions, to the public cloud. Clone it or add your own. Each rule matches by application, file type, and direction (upload, download, or both) and names the analysis destination: public-cloud or private-cloud. Attach the profile to allow rules directly or, more practically, through the Security Profile Group.

      Signature updates

      With a subscription, set how often the firewall checks for new WildFire signatures at ; the shortest interval gives near real-time protection. Without one, WildFire signatures still arrive bundled in the daily Antivirus package.

      Exam tip

      "Files from decrypted traffic aren't showing up in WildFire" has a specific answer: enable Allow forwarding of decrypted content under Device > Setup > Content-ID. Decryption alone isn't enough.

      12.4

      Submissions, reports, and verdict disputes

      Confirm the file went, read what came back, and push back if WildFire is wrong.

      • Did it upload? In the CLI, debug wildfire upload-log show lists recent uploads and their status.
      • What was the verdict? lists each analyzed file with its verdict. The detailed view's WildFire Analysis Report tab shows the full report: the behaviors observed in each sandbox environment, network activity, files created, and more, with links to download a PDF of the report and, for malware, the sample itself.
      • The bigger picture: the WildFire portal (wildfire.paloaltonetworks.com) shows submissions for all of your firewalls by serial number, with dashboards and reports.
      • Wrong verdict? From the report tab in the detailed log view, use the link to report an incorrect verdict and suggest the right one; you can also do it from the portal.
      admin@PA-VM> debug wildfire upload-log show

      In the field

      When a malware verdict comes back, the first question is who else received the file. The WildFire Submissions log tells you which user and host got the first copy; search the Traffic and Threat logs for the file's hash and destination to find any others delivered before the signature arrived.

      Watch out for

      • Wait for it. The guide's detailed steps say analysis can take 5 to 15 minutes, and the WildFire Submissions log stays empty until there's a verdict. Use the time to read the analysis-report section of this module. Don't reload the baseline or redo steps.
      • Why turn the other profiles off? With Antivirus or inline ML active, the test file could be caught locally before WildFire ever sees it. The lab isolates WildFire so you can watch the cloud do its job. In production, all the profiles work together.
      • The test file is harmless. It's built to be judged malicious so you can see a malware verdict safely.
      • Download the file, don't just open the link. The firewall forwards files it sees transferred; save it when Firefox asks.
      • If upload-log shows nothing, confirm the commit finished and that the rule the client's traffic matches uses Corp-Profiles-Group (check the Traffic log's rule column).

      Summary and self-check

      • WildFire analyzes unknown files and links from firewalls worldwide, returns verdicts, and distributes signatures and PAN-DB updates.
      • The firewall hashes each file; known hashes get the existing verdict; unknown files are forwarded unless signed by a trusted signer or over the size limit.
      • Verdicts: benign, grayware, malicious, phishing.
      • Free forwarding covers Windows PE files with daily signatures; the subscription adds many file types and real-time signatures; Advanced WildFire adds analysis for evasive malware. Analysis can be public cloud, private (WF-500/WF-600), or hybrid.
      • Configure Device > Setup > WildFire (size limits, benign and grayware reporting), decrypted content forwarding (Device > Setup > Content-ID), a WildFire Analysis profile, and the update schedule.
      • Verify with debug wildfire upload-log show and the WildFire Submissions log; read reports there or in the portal; report incorrect verdicts.
