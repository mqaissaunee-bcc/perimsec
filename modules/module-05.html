    Part A

    Zones and interfaces

    Dividing the network, and deciding how the firewall attaches to each piece.

    5.1

    Segmentation and security zones

    A flat network lets anyone who gets in reach everything. Segmentation puts doors between the rooms.

    Network segmentation divides a network into parts with different security needs, so that access between them can be controlled. Good segmentation starts with the business, not the wiring: who needs to reach what? Customer card data, HR records, the public web servers, and the sales team's laptops have very different owners, risks, and regulations. Apply the principle of least privilege: each group gets access to what it needs and nothing else. Regulatory requirements such as PCI DSS for card data often make some of these boundaries mandatory.

    On the firewall, segments become security zones. A zone is a logical group of interfaces whose networks share a trust level and a set of security needs. Zone names are yours to choose: Users_Net, Extranet, PCI, Internet. Security policy is then written between zones, as in "Users_Net may reach Extranet with these applications."

    Two defaults shape everything that follows:

    • Traffic between two different zones (interzone) is denied unless a rule allows it.
    • Traffic that stays within one zone (intrazone) is allowed unless a rule blocks it.

    So every zone boundary you draw is a place where nothing passes until you say so. That is the Zero Trust idea from Module 1 put into practice: inspect north-south traffic at the perimeter and east-west traffic between internal zones.

    Think of it this way

    Zones are the rooms of a building and policy rules are the keycard readers on the doors between them. Moving around inside one room needs no badge. Every door between rooms is locked until someone programs the reader.

    Common misconception

    "Put all the internal networks in one Trust zone and the internet in Untrust." It works, but because intrazone traffic is allowed by default, an infected laptop can reach the payroll server with no rule ever being checked. More zones means more doors.

    5.2

    Interfaces and zone types

    Zones are made of interfaces, and the interface type decides the zone type.

    The data plane controls the in-band network interfaces: physical ports such as ethernet1/1, and logical interfaces such as the subinterface ethernet1/1.10. Three rules govern how they combine with zones:

    • Each interface belongs to exactly one zone.
    • A zone can contain many interfaces.
    • An interface that is not assigned to a zone does not process traffic.

    Every zone has a type, and each type accepts only certain interfaces:

    Zone typeInterfaces it accepts
    Layer 3Layer 3 interfaces and subinterfaces, VLAN interfaces, loopback interfaces, tunnel interfaces
    Layer 2Layer 2 interfaces
    Virtual WireVirtual wire interfaces
    TapTap interfaces
    TunnelNone. Used for inspecting the contents of tunnels such as GRE, not for interfaces

    The MGT and HA interfaces are never in a zone. Create zones at : give the zone a name, choose its type, and add interfaces of the matching type. You can also assign the zone from the interface's own configuration dialog.

    5.3

    Tap, virtual wire, and Layer 3 deployments

    Three ways to attach the firewall, from watching quietly to routing everything.

    Tap: watch without touching

    A tap interface connects to a switch's SPAN or mirror port and receives a copy of the traffic. The firewall identifies applications, users, and threats and logs them, but it cannot block, shape, or change anything, because the original traffic never passes through it. Tap mode is for evaluations and audits: install the firewall for a few weeks, then use the Traffic log to show what is really on the network and to design the Security policy you will enforce later.

    Virtual wire: inline and invisible

    A virtual wire binds two interfaces together through a virtual wire object. Neither interface has an IP or MAC address, so the firewall drops into an existing link like a cable. Adjacent switches and routers need no configuration changes. Unlike tap mode, the firewall is inline, so it can enforce policy with App-ID, Content-ID, User-ID, and decryption, and it can even perform NAT.

    The virtual wire object, at , has a few options worth knowing:

    • Tag Allowed lists the 802.1Q VLAN tags the virtual wire accepts; 0 means untagged traffic.
    • Multicast Firewalling applies Security policy to multicast traffic instead of forwarding all of it.
    • Link State Pass Through brings one side down when the other loses link, so neighboring devices notice the failure and can fail over.

    Layer 3: route between networks

    A Layer 3 interface has an IP address and routes traffic between networks through a virtual router. Layer 3 mode includes everything virtual wire does plus routing, routing protocols, and site-to-site VPN. It usually requires changing the network around the firewall: hosts and routers must use the firewall's interface addresses as their gateways. The NDG lab firewall uses Layer 3 interfaces.

    5.4

    Configuring Layer 3 interfaces

    Each Layer 3 interface needs three things before it carries traffic: a virtual router, a zone, and an address.

    Open the interface at and set the Interface Type to Layer3. The dialog has three tabs that matter here:

    • Config: choose the virtual router and the Layer 3 security zone.
    • IPv4: a static address in CIDR notation, such as 192.168.1.1/24, or DHCP client. For IPv6 there is an IPv6 tab, but IPv6 must first be enabled firewall-wide at .
    • Advanced: the Interface Management Profile, static ARP (IPv4) or neighbor discovery (IPv6) entries, LLDP, NDP proxy, and dynamic DNS.

    Interface Management Profiles

    The MGT port is not the only way to manage a firewall. An Interface Management Profile, created at , lets a data interface answer management services: ping, HTTPS, SSH, SNMP, response pages, User-ID services, and others, optionally only from permitted addresses. You attach it on the interface's Advanced tab. It applies to interfaces that have IP addresses: Layer 3, loopback, VLAN, and tunnel.

    A common pattern: a profile that allows only ping on internet-facing interfaces, and a profile that allows ping plus response pages (for URL filtering block pages, Module 11) on user-facing interfaces. Never enable HTTPS or SSH management on an internet-facing interface.

    Exam tip

    If you can't ping a firewall interface from a host on its own subnet, the usual cause is that no Interface Management Profile allowing ping is attached. Security policy rules do not control pings to the firewall's own interface; the profile does.

    Subinterfaces

    A Layer 3 subinterface such as ethernet1/3.20 splits one physical port into several logical interfaces, each with its own address and zone. The firewall decides which subinterface receives a packet by its 802.1Q VLAN tag (1 to 4094), by a source-IP classifier, or both. This is how one cable to a trunked switch port can carry the Engineering, HR, and data center VLANs into three separate zones, each with its own policy.

    To create one, select the parent interface and click Add Subinterface. The number after the dot is just the subinterface ID; the VLAN tag is a separate field, though matching them makes life easier.

    5.5

    Virtual routers and static routes

    Layer 3 interfaces route through a virtual router. It decides where each packet goes, and that decision also decides its destination zone.

    A virtual router holds the routing table for the interfaces assigned to it. Configure it at . On the General tab you add the interfaces it may forward through; their subnets appear automatically as connected routes. Beyond that, a virtual router supports:

    • Static routes that you enter yourself.
    • Dynamic routing with BGP, OSPFv2, OSPFv3, and RIPv2.
    • Multicast routing with PIM-SM and PIM-SSM.

    A firewall can have more than one virtual router, for example to keep a guest network's routing completely separate, and routes can point from one virtual router to another. Newer PAN-OS releases also offer an Advanced Routing Engine that calls these logical routers; the concepts are the same.

    The default route

    Almost every firewall needs a static default route, 0.0.0.0/0, pointing to the internet router. Add it at with the destination, the egress interface, and the next-hop address.

    How the firewall picks a route

    1. Find every active route that contains the destination address.
    2. Choose the one with the longest prefix, the most specific match. A /24 beats a /16, and anything beats the /0 default.
    3. If several routes have the same prefix length, choose the one with the lowest metric.

    The egress interface of the chosen route tells the firewall the destination zone. This is why routing comes before policy in the packet flow you will study in Module 6: the firewall cannot decide which Security policy rule applies until it knows where the packet is going.

    Failover with path monitoring

    You can configure two default routes to two ISPs with different metrics. The lower metric is used normally. Path monitoring on a static route pings one or more stable upstream addresses; if they stop answering, the firewall removes the route, and traffic shifts to the next-best route. It keeps testing, and when the path recovers the route returns automatically.

    To troubleshoot, the virtual router's More Runtime Stats shows the full routing table (RIB), the forwarding table actually used for packets (FIB), and the status of monitored paths.

    Watch out for

    • Masks. Enter every interface address with its /24. Without it the address becomes a /32 and nothing on the subnet is reachable.
    • The first client test is supposed to fail. Before the profiles exist, the firewall ignores pings and SSH on ethernet1/2. That is the lesson, not a mistake.
    • Why the firewall's own pings work with no Security rules. Traffic the firewall itself originates, such as a CLI ping, is not checked against Security policy. Traffic passing through the firewall is, starting in Lab 5.
    • Two paths to one subnet. In this lab the management interface (192.168.1.254) and ethernet1/2 (192.168.1.1) sit on the same 192.168.1.0/24 network. That keeps the lab simple; in production the management network is kept separate (Section 2.2).

    Summary and self-check

    • Segmentation applies least privilege to the network. Security zones group interfaces with the same security needs, and policy is written between zones.
    • Interzone traffic is denied by default; intrazone traffic is allowed by default. More zones means more controlled boundaries.
    • Each interface is in one zone; a zone can hold many interfaces; unassigned interfaces pass no traffic. Interface type must match zone type. MGT and HA are never in zones.
    • Tap mode watches a SPAN port and cannot block. Virtual wire is inline with no IP addresses or network changes. Layer 3 routes, and adds routing protocols and VPN.
    • A Layer 3 interface needs a virtual router, a zone, and an address. Interface Management Profiles control management services, including ping, on data interfaces. Subinterfaces split one port by VLAN tag into separate zones.
    • The virtual router chooses the longest-prefix match, then the lowest metric. The egress interface of the chosen route determines the destination zone. Path monitoring removes a failed static route so a backup can take over.
