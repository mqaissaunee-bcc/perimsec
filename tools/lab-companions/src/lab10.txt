title: Blocking Unknown Threats with WildFire
lede: Signatures only stop malware someone has already seen. You create a WildFire Analysis profile that sends files to the public cloud sandbox, isolate it in the profile group, download a harmless test file built to look like zero-day malware, confirm the upload from the CLI, and read the verdict and analysis report.
snapshot: edu-210-11.0a-10.xml
uses: Module 12, sections 12.2 to 12.4

= overview | What this lab is for | What this lab is for | Prepare
Lab 8's profiles match known threats. A brand-new piece of malware has no signature yet, so it walks past them. {{wildfire|WildFire}} closes that gap: the firewall forwards unknown files to a cloud sandbox, which runs them, watches what they do, and returns a {{verdict|verdict}} (benign, grayware, phishing, or malicious). A malicious verdict produces a signature that protects every subscribing firewall.

This lab is mostly about watching that flow happen and reading what WildFire tells you, which makes it shorter than most. The wait for a verdict is real; plan for it.

- **You'll leave with:** a Corp-WF profile in Corp-Profiles-Group, a submitted test file, its verdict, and its PDF analysis report.
- **Builds on:** ->Mod 12<-. Simulation 12.1 follows files through WildFire at different license levels.
- **Sets up:** the capstone's Corp-WF profile.

= walkthrough | Walkthrough | Walkthrough of the detailed steps | Do the lab
@baseline

## 2.2 Create a WildFire Analysis profile
1. Go to [[Objects > Security Profiles > WildFire Analysis]] and click **Add**.
2. Name `Corp-WF`, description `WildFire profile for Corp security rules.`
3. Click **Add** for a rule: name `All_Files`, Applications **any**, File Types **any**, Direction **both**, Analysis **public-cloud**. Click OK.
!shot The Corp-WF profile showing the All_Files rule sending any file type to public-cloud.

## 2.3 Isolate WildFire in the profile group
1. Go to [[Objects > Security Profile Groups]] and open **Corp-Profiles-Group**.
2. Set **WildFire Analysis Profile** to **Corp-WF**, and set every other profile to **None**. Click OK.
!why Why turn the others off? | With Antivirus or its inline machine learning active, the test file could be caught on the firewall before WildFire ever sees it. Turning them off lets you watch the cloud do its job alone. In production, all the profiles work together.
!stuck A lab-only setting | The next lab's baseline restores a normal group, so you don't need to undo this. But never leave a real firewall like this.

## 2.4 Update WildFire settings
1. Go to [[Device > Setup > WildFire]] and click the gear on **General Settings**.
2. Check **Report Benign Files** and **Report Grayware Files**. Leave the rest. Click OK.
3. In [[Policies > Security]], open **Allow-PANW-Apps**. On **Source**, set Source Address to **Any**. Click OK.
4. Commit.
!why Why change Allow-PANW-Apps? | The rule was limited to the firewall's management address. WildFire uploads and verdict lookups (`paloalto-wildfire-cloud`) need to match it reliably, so the lab widens the source.
!tip Benign and grayware reporting | By default the WildFire Submissions log shows only malicious verdicts. These boxes make benign and grayware results visible too, which is useful when you're learning what gets sent.

## 2.5 Test the profile
1. In a new Firefox tab, open `http://192.168.50.80/wildfire-test-pe-file.exe` and click **Save** when prompted. Close the tab.
2. Open **Remmina**, double-click **Firewall-A**, and check the upload log. It may take a minute or two to show the file.
$fw debug wildfire upload-log show
3. Exit the SSH session.
$fw exit
!stuck Download the file, don't just open the link | The firewall forwards files it sees transferred. Make sure Firefox actually saves it.
!shot The CLI showing wildfire-test-pe-file.exe in the upload log.

## 2.6 Examine the WildFire analysis
1. Go to [[Monitor > Logs > WildFire Submissions]]. Refresh until `wildfire-test-pe-file.exe` appears. Analysis can take **5 to 15 minutes**; the log stays empty until there's a verdict.
2. Click the magnifying glass on the entry to open the **Detailed Log View** and note the **Verdict**.
3. Select the **WildFire Analysis Report** tab and click **Download PDF**.
4. Scroll through the report. Section 3.1 describes the sandbox environment and what the file did.
!tip Use the wait | Read Module 12's section on analysis reports while you wait. Don't reload the baseline or redo steps; that just restarts the clock.
!shot The WildFire Submissions log showing the test file with a malicious verdict.
!shot The WildFire analysis report PDF open in Firefox.

= reference | Reference | WildFire reference | Understand
### Verdicts
| Verdict | Means | Default logging |
| benign | Safe | Only if Report Benign Files is on |
| grayware | Unwanted but not malicious (adware, trackers) | Only if Report Grayware Files is on |
| phishing | A phishing page or link | Logged |
| malicious | Malware; a signature will follow | Logged |

### Where to look
| Question | Where |
| Was the file sent? | `debug wildfire upload-log show` |
| What was the verdict? | [[Monitor > Logs > WildFire Submissions]] |
| What did it do? | The entry's WildFire Analysis Report, or the PDF |
| Is the firewall connected to WildFire? | `show wildfire status` |

$fw show wildfire status

= stuck | Where people get stuck | Where people get stuck | Understand
| Symptom | Likely cause | Fix |
| upload-log shows nothing | Commit not finished, or the client's traffic matches a rule without the group | Check the Traffic log's Rule column for the download; confirm that rule uses Corp-Profiles-Group. |
| Submissions log empty after 5 minutes | Still analyzing | Wait up to 15 minutes and refresh. |
| File blocked instead of uploaded | Antivirus still in the group | Set the other profiles to None (task 2.3). |
| You opened the link but didn't save | Download not completed | Request it again and Save. |
| Can't find Download PDF | You're on the General tab | Switch to the WildFire Analysis Report tab. |

= production | In production | How this looks on a real firewall | Understand
- **WildFire alongside everything else.** Production groups include Antivirus, Anti-Spyware, Vulnerability, URL Filtering, and WildFire together. Inline machine learning stops many threats on the firewall in real time; WildFire covers what's left.
- **Get verdicts fast.** With a WildFire license, new signatures arrive within minutes. Set the WildFire content update schedule to the shortest interval available.
- **Mind privacy and regulation.** Some organizations can't send certain files to a public cloud. Options include a regional cloud, a private cloud appliance (WF-500), or excluding file types.
- **Decrypt to see files in HTTPS.** Most downloads are encrypted. Without decryption (Lab 12), the firewall never sees the file to forward it.
- **Other vendors:** Fortinet FortiSandbox, Cisco Secure Malware Analytics (Threat Grid), and Check Point SandBlast do the same job.

= selfcheck | Check yourself | Check yourself | Wrap up
?? Why can't Lab 8's antivirus profile stop a true zero-day file?
=> It matches signatures, and a zero-day has no signature yet.

?? Why does the lab set every other profile in the group to None?
=> So nothing on the firewall stops the file before WildFire analyzes it.

?? The WildFire Submissions log is empty right after the download. Is something wrong?
=> Not necessarily. Entries appear only after a verdict, which can take 5 to 15 minutes.

?? Which CLI command confirms the file was actually sent?
=> `debug wildfire upload-log show`.

?? What do Report Benign Files and Report Grayware Files change?
=> They make benign and grayware verdicts appear in the WildFire Submissions log, not just malicious ones.
