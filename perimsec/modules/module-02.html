Initial Firewall Configuration

Every firewall starts the same way: one cable to the management port, a default login, and a short list of settings that must be right before anything else will work. Get these wrong and updates fail, logs lie about the time, or you lock yourself out.

    Part A

    Getting in

    First contact with a new firewall and its management interface.

    2.1

    First access

    A new firewall has no idea what network it is on. You reach it through one of two doors built for exactly this moment.

    Initial configuration happens through either the dedicated out-of-band management (MGT) interface or a serial console connection. Out of the box:

    SettingDefault
    MGT address on most hardware models192.168.1.1/24
    MGT address on VM-SeriesDHCP client (gets an address from the network)
    Predefined administratorUsername admin, password admin

    To use the web interface on a hardware firewall, set your laptop to an address such as 192.168.1.2/24, connect to the MGT port, and browse to https://192.168.1.1. Expect a certificate warning: the firewall ships with a self-signed certificate.

    Four ways to manage a firewall

    • Web interface over HTTPS. Where you will spend most of this course.
    • CLI over SSH or the serial console. Fast for troubleshooting and the only option before the network is configured.
    • XML and REST APIs for automation and integration with other tools.
    • Panorama, which pushes configuration to many firewalls at once.

    The CLI has two modes. Operational mode, shown by a > prompt, is for viewing status and running commands. Type configure to enter configuration mode, shown by #.

    admin@PA-VM> show system info      # model, serial, PAN-OS version, MGT IP
admin@PA-VM> configure
admin@PA-VM# show deviceconfig system   # candidate config for system settings

    The first login

    PAN-OS forces you to change the predefined admin password at the first login. The new password must have at least eight characters, including one uppercase letter, one lowercase letter, and one number or special character. These rules cannot be changed and apply only to the predefined admin account; you set the policy for other accounts separately.

      Getting around the web interface

      The top of the web interface has tabs for each functional area: Dashboard, ACC, Monitor, Policies, Objects, Network, and Device. The Commit button applies your changes (Module 3), and the Tasks button at the lower right shows the progress of commits and downloads. When you edit an object, required fields are highlighted in red and tabs that still need information are underlined in red; the OK button stays unavailable until everything required is valid. Throughout this course, menu locations are written like this: .

      Common misconception

      "I clicked OK, so the change is live." In PAN-OS, OK only saves the change to the candidate configuration. Nothing takes effect until you commit. Forgetting to commit is the most common reason a lab step "doesn't work."

      2.2

      The management interface

      Give the firewall a permanent address on your management network and decide who may reach it.

      Configure the MGT interface at . It can use a static address or run as a DHCP client. A static configuration needs at least three things: an IP address, a netmask, and a default gateway. The gateway must be on the same subnet as the address, or the firewall cannot reach anything beyond its own segment, including the update servers.

      The same dialog controls who and what can use the interface:

      • Permitted IP addresses. If the list is empty, any host that can reach the port can attempt to log in. Add your administrator workstations or management subnet. Be careful: if you leave your own address out and commit, the firewall stops answering you.
      • Management services. HTTPS and SSH for the web interface and CLI, ping for reachability, plus others such as SNMP and User-ID. Leave HTTP and Telnet off; they send credentials in cleartext.

      The MGT interface is not part of any security zone and does not pass user traffic. To allow management on a data interface instead, you attach an Interface Management Profile to it (Module 5).

        In the field

        Put the MGT interface on a dedicated management network that is never reachable from the internet. Many published firewall compromises began with a management interface exposed to the internet. Restricting permitted IPs is your second line of defense, not your first.

        Part B

        Services, licenses, and software

        What the firewall needs from the outside world, and how it gets it.

        2.3

        Identity and core services

        Name the firewall, tell users what they are logging in to, and connect it to time and name resolution.

        At , under General Settings:

        • Hostname and domain both default to the model name. Give each firewall a unique name; it appears in logs, in the CLI prompt, and in Panorama.
        • Login banner displays a message on the login page, typically an authorized-use warning required by your organization's policy.
        • Latitude and longitude place the firewall on the world maps in the ACC and Monitor tabs.
        • The Accept DHCP server hostname/domain options appear only when the MGT interface uses DHCP.

        At :

        • DNS servers are required. The firewall resolves the names of its update and license servers, and of any FQDN address objects you create later. With no DNS, license retrieval and dynamic updates fail.
        • NTP servers are optional but recommended. Accurate time keeps log timestamps trustworthy, lets you correlate events with other systems, and matters for certificate validity checks.

        Think of it this way

        Investigating an incident with logs from five devices whose clocks disagree is like interviewing witnesses whose watches are all set differently. NTP is how everyone agrees what time it was.

        2.4

        Service routes

        By default, the firewall uses its MGT interface to reach every external service. Sometimes that is the wrong path.

        DNS, NTP, update servers, license servers, syslog, email alerts, authentication servers: all of these are reached through the MGT interface unless you say otherwise. That works when the management network has a route to them. When it doesn't, for example when the management network is isolated from the internet by design, you configure a service route that sends a particular service out a data interface instead.

        Configure service routes at . You can keep the default for everything, or choose Customize and set a source interface and source address for individual services.

        Activity 2.1

        Default MGT path or service route?

        About 4 minutes. For each situation, decide whether the default works or you need a service route.

        Exam tip

        If updates or license retrieval fail, check three things in this order: DNS is configured, the MGT default gateway is correct, and, if the MGT network has no internet access, a service route exists for the update service.

        2.5

        Licenses, content updates, and software

        A firewall without licenses and current content is a very expensive port-based firewall.

        Activation

        Register the firewall with Palo Alto Networks Support: hardware by its serial number (shown on the Dashboard), VM-Series with the authorization codes from your order. Then manage licenses at , where you can:

        • Retrieve license keys from the license server for licenses already associated with the firewall's serial number.
        • Activate a feature using an authorization code for a newly purchased subscription.
        • Manually upload a license key when the firewall has no internet access.

        Dynamic updates

        Dynamic updates are content packages separate from PAN-OS itself: Applications and Threats (new App-IDs and vulnerability and spyware signatures), Antivirus, WildFire, and others depending on your licenses. Manage them at . Click Check Now to see what is available, then download and install. For each update type you can set a schedule that checks for new content and then either just downloads it or downloads and installs it. If a new content release causes a problem, you can revert to the previously installed version.

        PAN-OS software

        Manage the operating system at : Check Now lists available releases, Download fetches one from the update server (or Upload installs one from your computer), and Install applies it, followed by a reboot. Before an upgrade, install current content updates (a new PAN-OS release can require a minimum content version), export a named configuration snapshot as a backup (Module 3), and read the release notes for the upgrade path.

        Guided problem 2.1

        "Retrieve license keys" fails

        You click Retrieve license keys from license server on a newly installed lab firewall and get an error that the server cannot be reached. The firewall's MGT address is 10.10.5.20/24 with gateway 10.10.6.1. Work out the cause. Try it on your own first; reveal one step at a time only as you need it.

        1. Retrieving licenses requires the firewall to resolve and reach the license server. Two things must work: DNS and a route out.
        2. Check the route first. The MGT address is in 10.10.5.0/24 (10.10.5.0 to 10.10.5.255). The gateway is 10.10.6.1.
        3. The gateway is in a different subnet, so the firewall has no reachable next hop. Nothing beyond 10.10.5.0/24 can be reached, including DNS servers elsewhere.
        4. Fix: set the gateway to the router address on 10.10.5.0/24 (for example 10.10.5.1), commit, then confirm DNS servers are configured under Device > Setup > Services and retry.
        2.6

        Resetting to factory defaults

        Sometimes the fastest fix is a clean start. There are two ways, depending on whether you still know the admin password.

        If you know the password, run this from the CLI:

        admin@PA-VM> request system private-data-reset

        It erases all logs and resets all settings, including the MGT address, so you will lose your connection. When it finishes, the firewall is back to its defaults.

        If you do not know the password, connect to the console port and reboot. During boot, type maint to enter maintenance mode, then choose Reset to Factory Default. Maintenance mode can also load a previous configuration file if the admin password was changed and lost.

        In the field

        Both methods destroy the configuration and logs. In production, export a configuration snapshot first if you can, and treat the logs as possible evidence if the reset is part of an incident.

        Before you start

        Watch out for

        • Permitted IPs. Before you commit the permitted-IP step, confirm your lab client's address is in the list. If you lock yourself out, use the lab's console access to fix it, or reload the starting configuration.
        • Forgetting to commit. If a setting seems to have no effect, check the Commit button and the Tasks window.
        • Updates in an isolated lab. Lab environments sometimes have limited internet access. Configuring the schedule is the goal; a download that fails because the lab cannot reach the update server is not a configuration error. Note it and move on.
        • Two sets of steps. If your lab guide offers high-level and detailed steps, use one or the other, not both. Try the high-level steps if you are comfortable; switch to detailed steps when stuck.

        ✓

        Summary and self-check

        • Initial access is through the MGT port or the serial console. Most hardware defaults to 192.168.1.1/24; VM-Series uses DHCP. The default login is admin/admin and must be changed at first login.
        • Manage the firewall through the web interface, the CLI, the XML and REST APIs, or Panorama. Changes go to the candidate configuration until you commit.
        • A static MGT configuration needs an address, netmask, and same-subnet gateway. Restrict permitted IPs, keep your own address in the list, and use HTTPS and SSH rather than HTTP and Telnet.
        • DNS is required for licensing and updates; NTP is strongly recommended for accurate logs.
        • External services use the MGT interface by default. A service route sends a service out a data interface instead.
        • Activate licenses at Device > Licenses, schedule content at Device > Dynamic Updates, and upgrade PAN-OS at Device > Software after current content and a configuration backup.
        • Reset to defaults with request system private-data-reset, or through maintenance mode on the console if the password is unknown.
