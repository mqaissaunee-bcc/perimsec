Capstone

One firewall, starting from a nearly empty configuration, built to a written specification: interfaces, routing, zones, User-ID, NAT, Security policy, URL categories, and a full set of Security Profiles. It is open book: your notes, this site, and your earlier labs are all fair game.

  • About 2 to 3 hours
  • NDG Online, Lab 14
  • Graded, plus the final exam in Canvas

How the capstone differs

Earlier labs told you each click. The capstone gives only objectives and tests, like a work ticket. Names must be spelled and capitalized exactly as written, because grading checks them. Every objective is something you have already done; the skill being tested is putting them together in the right order and proving each part works.

Before you start

Read the guide carefully

  • The zone is Users, not Users_Net. Earlier labs used Users_Net; the capstone's zone is named Users, and one line calls it "the User zone." Name it exactly Users.
  • Two profile descriptions are swapped. The guide says Corp-AV should "block vulnerabilities" and Corp-Vuln should "block viruses." Go by the profile type: an Antivirus profile stops viruses and malware, and a Vulnerability Protection profile stops exploits (Module 10). Use the source profiles the guide suggests for each.
  • Same names, different rulebases. Users_to_Internet and Extranet_to_Internet are names for both NAT rules and Security rules. That's allowed, because NAT and Security policy are separate rulebases, but keep track of which one you're editing.
  • "Log access to all web categories." Allow doesn't write a URL Filtering log entry; alert does (Module 11). Plan your Corp-URL settings with the final test in mind.
  • "All outbound traffic" and rule order. Decide which source zones count as outbound, and where Block_Bad_URLs has to sit so it isn't shadowed (Modules 6 and 11).
  • "All applicable" rules. Profiles inspect allowed traffic; think about which rules the group belongs on (Module 10).
  • The default route needs a next hop. The guide names the route but not the gateway; your Lab 4 notes and the CLI ping tests tell you what it must be.

Proving it works

Check each test as it passes. When something fails, work through the flow from Module 6 in order: is the interface up and in the right zone, is there a route, does NAT match, which Security rule matched (Traffic log, Test Policy Match), and did a profile block it (Threat, URL Filtering, and Data Filtering logs)?

Stuck?

The fastest tools are the ones you've used all term: Simulation 6.2 for rule order, Simulation 7.1 for NAT zones, Simulation 14.2 for log filters, and the Traffic log's Rule and Session End Reason columns for what actually happened.
